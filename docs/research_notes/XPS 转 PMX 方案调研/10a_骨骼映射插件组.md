# 骨骼映射 / 骨架转换组调研：4 个插件 + mmd_tools_helper 对照

只读调研，没有修改或新建任何文件。每节开头给出插件根目录的绝对路径；表格里写成 `文件:行号` 的引用，都相对于该节的根目录。

**结论：**
- **Convert_to_MMD5** 是本组最成熟的实现，建议作为新插件骨骼部分的主体来源（ABSORB）。
- **xps_to_mmd-main** 的代码大多已被 Convert_to_MMD5 取代，只吸收其中的检查逻辑、规格文档和离线测试。
- **bones_renamer-master** 只要它的 CSV 数据，代码不要。
- **bone_detection_lite** 只是一个界面原型，没有可用的映射存储。

另外几个需要先知道的问题：
- 几份数据对同一个 XPS 骨架给出的"标准答案"互相矛盾。例如 `spine lower`，在 3 份数据里映射成 上半身，在另外 2 份里映射成 下半身。
- 有的插件因为命名约定不一致，修正步骤会静默地什么都不做。
- mmd_tools 设置付与源骨时，如果源骨不存在，会悄悄写入无效值而不报错。

这三类问题正是映射检查器最该抓的（见第 5 节）。

- `ui.py:159-165` 写的是 `row.prop_search(data, "bones", data, "bones")`。传进去的是集合属性，而不是字符串或指针属性，没法当槽位输入框用。`BoneDetectionProperties`（`__init__.py:35-61`）里也根本没有槽位字符串属性。状态图标永远是对勾（`ui.py:167`）。

  - `.L↔.R`、`_L↔_R`

  - **问题**：规则里没有小写的 `left/right`，所以 XPS 风格的名字（如 "arm left shoulder 1"）不会自动镜像。

### 2.8 自动识别启发式（skeleton_identifier.py）

整体是纯拓扑 + 几何，没有骨名正则表；唯一用到名字的地方是第 7、8 步。

1. **找脊柱链** `_find_spine_chain`（112-143）
   - 先算 height = 所有骨头 head.z 的跨度。
   - 中轴候选：|head.x| < 0.1·height 的骨；没有就取 |x| 最小的 5 根。
   - 在候选里找"左右两侧都有子骨"的骨（某个子骨 x>0.01，另一个 x<-0.01），按 `z + 0.01·min(子骨数, 50)` 打分，最高者当头骨。
   - 没有这种骨时，就取有子骨的骨里最高的那根。
   - 从头骨沿父级回溯到根，反转后就是脊柱链。
2. **找分叉点** `_find_fork_points`（146-200）
   - 阈值 x_thresh = max(0.01·链高, 0.01)。
   - 链上每根骨（最后两根除外）只要链外子骨里同时有 x>阈值 和 x<-阈值 的、且子树深度 ≥3，就算分叉点。
   - 直接子骨找不到两个分叉点时，再看孙辈。
   - 按 z 排序：最低的是腿分叉，最高的是臂分叉；只有一个时按链中点高度判断是腿还是臂。
3. **分配脊柱槽** `_map_spine`（207-274）
   - 链首 → 全ての親（当腿分叉不在链首时）。
   - センター = 腿分叉骨。但如果它的父骨 |x|<0.01 且只有一个子骨，就改用父骨（比如优先 root hips，而不是 unused bip001 pelvis）。
   - 腿分叉和臂分叉之间的骨：第 1 根 → 上半身，第 2 根 → 上半身1。
   - 臂分叉骨 → 上半身2。
   - 臂分叉之上：第一根 → 首，最后一根 → 頭。
4. **识别手臂** `_map_arms` / `_assign_arm`（281-355）
   - 从臂分叉骨的链外侧向子骨（或孙辈）开始。
   - 候选有多个时，优先"子孙里有手"的（`_is_hand_bone`：至少 3 个子骨的子树深度 ≥3），再取子树最深的。
   - `_trace_arm_chain`（358-375）最多走 8 步，到手就停；遇到多个子骨时沿子树最深的走。
   - 按链长分配：
     - ≥4 节 → 肩 / 腕 / ひじ / 手首。
     - =3 节 → 如果第一节长度 < 0.7×第二节，判为 肩 / 腕 / 手首，否则判为 腕 / ひじ / 手首。
     - =2 节 → 腕 / 手首。
5. **识别手指** `_identify_fingers`（400-445）
   - 从手骨的每个子骨开始，沿"唯一子骨"一路走成链，至少 2 节才算一根手指。
   - 链有 ≥4 节时去掉首节（当作掌骨）。
   - 拇指 = 第一节方向与所有手指平均方向偏差最大的那条，取前 3 节填 thumb_0/1/2。
   - 其余按与拇指根的距离从近到远，依次是 食指 / 中指 / 无名指 / 小指 的 _1/_2/_3。
6. **识别腿** `_map_legs` / `_assign_leg`（452-504）
   - 从腿分叉骨的链外侧向子骨（或孙辈）里取子树最深的。
   - `_trace_limb_chain` 最多走 6 步。
   - 如果第一节和第二节的 head 距离 <0.01（腰キャンセル 这类控制骨），跳过第一节。
   - ≥4 节 → 足 / ひざ / 足首 / 足先EX；3 节取前三；2 节取前二。
7. **识别眼睛** `_map_eyes`（537-582）
   - 在頭的子骨和孙骨里找。左候选 x>0.02，右候选 x<-0.02。
   - 要求 |x|、y、z 三个方向的差都 <0.01，才算对称的一对。
   - 打分：两骨 z 之和；如果两个名字都像眼睛，再加 1000。"像眼睛"指 `_is_eye_name`（529-534）判断为含 eyeball / eye / 目，且不含 eyelid / eyebrow / eyelash / brow / lash。
   - 取分最高的一对。
8. **XPS 标准名优先** `_prefer_xps_standard_names`（70-105）
   - 读入 presets/xna_lara.json。
   - 骨架里存在的 XPS 标准名，只有和另一根标准名骨处在同一条父链上才算数（排除孤立的同名残骨）。
   - 算数的名字覆盖拓扑结果；拓扑结果里与之重复的槽被清空。
9. `_subtree_depth`（592-602）用全局缓存，换骨架前必须调用 `clear_cache()`。

**辅助骨分类** `classify_helpers`（helper_classifier.py:19-98），对未映射的骨按以下优先级判断：

| 优先级 | 条件 | 类别 |
|---|---|---|
| 1 | 已映射 | mapped |
| 2 | `_dummy_` / `_shadow_` 前缀 | ignore |
| 3 | 頭的后代 | other（头发和脸部骨，避免被误判成扭转骨） |
| 4 | 手首的后代 | other |
| 5 | 最近的已映射祖先是 センター | 直接子骨且 \|x\|<0.02 → pelvis；\|x\|≥0.02 → preserve；其余 → other |
| 6 | 投影在上臂或前臂段上（t∈[-0.15,1.15]，垂直距离 <0.35×段长） | twist |
| 7 | 投影在大腿段上 | preserve |
| 8 | 祖先是大腿 | preserve |
| 9 | 祖先是脊柱 | \|x\|≥0.02 → preserve（胸部）；否则 → merge |
| 10 | 其余 | other |

前置条件：左右 ひざ、左右 足首、全ての親 必须存在（62-66），否则报错。

| 左/右足ＩＫ | ひざ.tail（即 足首 的 head） | head + (0, 0.5L, 0) | 足IK親 | 否 |

约束设置：

| 骨与约束 | 设置 |
|---|---|
| ひざ：IK | 目标 足ＩＫ，chain_count 2，iterations 200；ik_min_x=0，ik_max_x=180°；use_ik_limit_x/y/z 都设为 True，但只给 x 设了范围，y/z 用 PoseBone 的现有值。xps_to_mmd 则显式把 y/z 设为 0（锁死），两边在这点上不同 |

| 足首：IK | 目标 つま先ＩＫ，chain 1，iterations 200 |
| 足首 → ひざ、つま先 → 足首：DAMPED_TRACK `mmd_ik_target_override` | influence 0，只是给 mmd_tools 导出器识别 IK 目标用 |

**为什么要建 `つま先`**（ik.py:86-91 的注释）：
- mmd_tools 导出时，只在带 IK 约束的骨（足首）的子骨里找 IK 目标；它会先找那个带 `mmd_ik_target_override`、并指回 足首 的子骨（exporter.py:540-557）。
- 而 足先EX 之后会被 D 骨步骤挪到 足首D 下面。
- 没有这根 つま先，导出后 つま先ＩＫ 就不是 IK 了。

代码没有设置 `mmd_bone.ik_rotation_constraint`，取默认值 1 rad。导出时 loopCount = iterations / `mmd_ik_loop_factor` = 200（exporter.py:520-524）。社区常见的标准值是：足ＩＫ 40 次 / 2 rad，つま先ＩＫ 3 次 / 4 rad。这是惯例，不是本代码里的数据，检查器可以把偏离当作提示项。

### 2.11 准标准骨（convert/semistandard.py）

这些 operator 只负责几何，中转结构交给 mmd_tools。

**腕捩 / 手捩**（50-162）：
- 基骨：腕 对应 腕捩 系列，ひじ 对应 手捩 系列。
- 沿基骨的位置 t：主捩 0.80；捩1/2/3 分别为 0.20 / 0.40 / 0.60（`_POS`，68 行）。
- 主捩：tail 沿臂方向，长度 `max(0.12×骨长, 1e-4)`，roll 等于基骨 roll。
- 子捩：tail 竖直朝 +Z，`align_roll((0,-1,0))`。它故意和主捩不对齐，好让 mmd_tools 建 dummy/shadow 中转。
- 所有捩骨都挂在基骨下、参与变形；基骨原来的子骨（ひじ / 手首）改挂到主捩下。
- 之后调用 `split_twist_weights` 切分权重。
- `_fix_twist_axis`：
  - 主捩设 `enabled_fixed_axis=True`、`fixed_axis=(axis.x, axis.z, axis.y)`（PMX 轴序）；axis 是 腕→ひじ（或 ひじ→手首）两个 head 的连线。
  - 主捩锁定全部位移，旋转只放开 Y 轴。
  - 子捩锁定位移。

**足D / ひざD / 足首D**（169-273）：
- 链条：足D ← 足，ひざD ← ひざ，足首D ← 足首。
- 足D 的父骨用 足 实际的父骨（通常是 腰キャンセル，211-214）；ひざD 挂 足D；足首D 挂 ひざD。
- head 等于源骨 head，tail = head + (0,0,0.1)。注意这里是绝对值，假定模型是米单位。
- 源骨的非链子骨（保留下来的辅助骨）改挂到对应 D 骨下，但 IK 骨、`_` 前缀骨、`つま先` 除外（230-243）。
- 足先EX 改挂到 足首D 下。

**肩P / 肩C**（280-351）：
- 肩P：head = 肩.head，tail = head + (0,0,0.08)，**父骨固定为 上半身2**（308、321 行；没有 上半身2 时用 肩 原来的父骨）。

`finalize` 参数：单独点按钮时为 True，会立刻写付与并执行 apply；一键流程里传 False，最后统一处理一次（27-35）。

**问题**：在 Convert_to_MMD5 的 XPS 映射下，脊柱是 上半身 → 上半身1（新插入）→ 上半身2（原 spine middle）→ 上半身3（原 spine upper）。肩 原本挂在 上半身3 下，被改挂到 上半身2 之后，就不再跟随 上半身3 转动。xps_to_mmd-main 的做法是"上半身3 存在就挂 上半身3"。建议把"肩P 的父骨应为最末一节上半身"列为检查项。

### 2.17 已知问题
- 一键转换默认会重新识别并覆盖用户核对过的槽位（`auto_identify=True`，pipeline.py:77）。面板上没有暴露关闭这个选项的开关。

### 3.4 Check Bones（check_bones_operator.py:15-160）——现成的检查器雏形

结果打印到控制台，报告栏只显示汇总。检查内容：
1. 未填充的槽位（45-58）。
2. 槽位填了、但骨架里不存在这根骨（"broken fills"，60-64）。
3. 辅助骨分类统计（会重新识别和分类，66-76）。
4. 每个顶点组中权重 >0.001 的顶点数（78-85）。
5. **孤儿顶点组**：有权重但没有同名骨，导出 PMX 时会丢失（87-96）。
6. **可疑权重骨**：有权重、名字里没有 MMD 字符、分类又不是 mapped/twist/pelvis/preserve 的骨（98-120）。
7. 没有权重的非 MMD 骨，最多列 20 个（122-142）。

判定标准：可疑骨、孤儿顶点组、broken fills 都为 0 时报"检查通过"，否则给警告。

它的不足：
- 不检查重复映射、左右侧、父子顺序。
- "是不是 MMD 骨"只靠一个单字符集合 `mmd_chars`（100 行）判断，名字里只要含其中任一个字就算 MMD 骨，非常粗糙。

- **补全**：控制骨、腿、指根骨的配方和 Convert_to_MMD5 相同，另外加了 上半身3 的插入（338-357）和 腰キャンセル 的付与（510-527）；肩 保留原父骨（185-190）。

- **肩C**（add_shoulder_p_bones_operator.py:160-199）：TRANSFORM 约束**混合模式 AFTER**，目标范围反向（+180→−180），付与源 肩P、比例 **−1.0**，并隐藏。到 8.5 步时 mmd_tools 判定 肩C 和 肩P 对齐，会删掉手工搭的中转、改为直连（mmd_tools core\bone.py:371-373）。
- **捩骨**（add_twist_bone_operator.py）：
  - 位置：`TWIST_SEGMENTS`（15-19）规定 腕→ひじ 段的主捩在 t=0.60，子捩在 0.25/0.50/0.75，主捩的 tail 指向段终点；ひじ→手首 段相同。
  - 扫描候选（44-101）：段两端之外的骨，要求不是 MMD 名、不是 `_` 前缀、有权重、head 到段的垂直距离 ≤0.3×段长、t∈[-0.1,1.2]；排除带手指子孙的兄弟骨。
  - 跨段去重（164-182）：同一根骨落在两段时，取 min(t, 1−t) 更大的那段，平局时偏向段起点。
  - 分配槽位（104-125）：有权重的顶点最多的候选当主捩，其余按 t 就近填子捩。
  - 有候选就改名（顶点组跟着名字走），没有就新建空骨。
  - 子捩手工搭 TRANSFORM，目标范围是 ±45°×i（454-461），付与比例 0.25/0.5/0.75，并隐藏。
  - 发生改名时，互换 腕 和 腕捩 的顶点组（289-307）。
  - 渐变分割（312-397）：t<0.05 的顶点不动；按 5 个锚点在相邻两骨间线性插值。上臂是"重新分配"（从 腕 移出）；前臂是"叠加"（保留 ひじ 的原权重再加上一份），每个顶点的总权重会超过 1，要靠后续归一化。

### 4.3 改名与检测算法
- `read_bones_dictionary`（19-35）：每行的第一格当预设名，其余格当骨名列表；只跳过完全为空的行。
- `rename_bones`（38-78）：
  - 按两个预设在列表里的下标取出两行，逐格配对成 `{源名: 目标名}`。
  - 遍历骨架的所有骨，命中且目标名非空就改名。
  - 身体表和手指表各跑一次（91-112）。
- `detect_matching_skeleton`（115-136）：对每个预设统计"名单里有多少根骨存在于当前骨架"，取最多的那个。

存在的 bug（都可以当检查器的反面案例）：
1. **表头被当成预设**：表头行 `中文` 被当成了第一个预设，而且是下拉框的默认值。这样可以把骨改成中文槽名，但这是无意中产生的功能。
2. **空分隔行成了预设**：第 6 行是一整行逗号（`,,,,…`），读出来不是空列表，于是变成了一个名字为 `''` 的预设。
3. **检测结果解析用子串匹配**（151-155）：检查"预设名是否是结果字符串的子串"。
   - `''` 是任何字符串的子串，所以排在分隔行之后的所有骨架（包括 xna_lara、Bip_001）都会落到 `''` 上，最后报 "No matching skeleton preset found"。
   - `mmd_japaneseLR` 会先被 `mmd_japanese` 子串命中，于是误判成 mmd_japanese。
4. **重复目标、后写覆盖**：mmd_japanese 和 mmd_japaneseLR 两行里，"父级"和"中心"都填的是 `センター`。从 mmd_japanese 改到 xna_lara 时，`センター` 先被映射到 `pelvis`，又被 `root hips` 覆盖，后写的赢。
5. **日志显示错误**：日志在改名之后才读 `bone.name`，所以显示的是"新名→新名"（73-74）。
6. **不检查名字冲突**：目标名已经存在于骨架时，Blender 会自动加 `.001`，代码不做检查。

### 5.2 数据已经支持、建议新增的检查

**A. CSV / 预设自检（不需要 Blender 就能跑）**
1. **左右成对**：每个 `left_*` 或 `.L` 槽都必须有对应的右槽。bone_detection_lite 只有 `腕捩.L`、没有 `.R`，就是反例。
2. **同列重复**：同一种骨架的同一列里，目标名不能重复。例如 bones_renamer 的 mmd_japanese 里 `センター` 出现了两次。
3. **MMD 名规范化**：
   - 指骨用全角数字（１２３０），`上半身2` 用半角。
   - 不允许空格（0mmd_japanese.json 的 `上半身 2`、`左親指 0` 是反例）。
   - 区分 `IK親`（半角 IK）和 `ＩＫ`（全角）。
   - 建议比较时先做 NFKC 归一化，但报告时显示原始差异。
4. **命名约定一致**：前缀式（`左腕`）和后缀式（`腕.L`）不能混用。xps_to_mmd 的 L1/L3 修正就是因为这个，全部静默不生效。
5. 空行、表头行、BOM、通配符（doa5lr 的 `*`）都要显式处理并报告。
6. **数据源互相矛盾时提示**：同一个源骨架在不同数据里给出矛盾的映射。例如 XNA Lara 的 spine lower：
   - 在 Convert_to_MMD5 的 xna_lara.json、xps_to_mmd 的 xna_lara_Inase.json、mmd_tools_helper 里都是 上半身；
   - 在 xps_to_mmd 的 xna_lara.json 和 bones_renamer 里是 下半身。

**B. 映射与当前骨架比对**
7. **必需槽未映射**，要在执行前拦截。至少包括：
   - Convert_to_MMD5 面板上带 `*` 的槽；
   - complete.py 缺了就会 KeyError 的 上半身、首、頭、肩、腕、ひじ、手首、足、ひざ、足首；
   - IK 需要的 ひざ、足首。
8. 其他映射问题：
   - 同一根源骨映射到多个槽；
   - 源骨不存在；
   - 目标名已经存在于骨架中（改名后会变成 `.001`）。
9. **识别与预设的分歧**：逐条列出自动识别结果和预设不一致的槽（"自动识别认为是 X，预设写的是 Y"）。
10. **骨架类型打分要报差距**：同时给出第一名和第二名的得分差，差距太小时提示人工确认。这样可以修掉 bones_renamer 那种子串误判。

**C. 几何与拓扑是否合理**
11. **侧别**：左槽骨的 head.x>0，右槽骨的 head.x<0（骨架局部坐标）。
12. **左右对称**：成对槽的 |x| 差、y 差、z 差都在容差内。识别器用的是 0.01 个单位，建议改成按身高比例。
13. **父子顺序**：
    - 手臂：腕 必须是 ひじ 的祖先，ひじ 必须是 手首 的祖先。
    - 腿：足 → ひざ → 足首 → 足先EX。
    - 脊柱：上半身 → … → 首 → 頭，可以复用 `auto_detect_upper_body_chain` 的父链走法，走不通就报错。
    - 手指：三节必须是连续的子骨链。
14. **脊柱段数**：报告源脊柱有几节、映射用了几节、哪些会新建并切分权重。要明确选定"新插 上半身1"还是"新插 上半身3"其中一种策略。
15. **手指**：
    - 每只手 5 条链，每条至少 2 节。
    - 拇指应该是方向偏离平均最大的那条。
    - 食指到小指按到拇指根的距离依次变远。
    - 4 节以上的链，首节视为掌骨。
16. **骨长比例与零长度**：
    - 用 肩 < 0.7×上臂 这类启发式检查比例。
    - head 重合（<0.01）说明控制骨混进了肢体链。
    - 上半身 和 下半身 head 重合时，提示需要做 Z 坐标校正。
17. **眼骨**：应在頭的子骨或孙骨里，是最高的一对对称骨；名字像 eyelid / brow / lash 的给警告。
18. **挂点**：
    - 肩P 应挂在最末一节上半身下（Convert_to_MMD5 固定挂 上半身2 是反例）。
    - `unused bip001 pelvis` 这类辅助骨应挂在 下半身 下。

**D. 权重**
19. 映射到的变形骨权重为 0：XPS 的 elbow 常见这种情况，作为信息级提示。
20. 控制骨（全ての親、センター、グルーブ、腰、腰キャンセル、操作中心、各 IK 骨）必须权重为 0，且 `use_deform=False`。
21. 每个顶点受影响的骨数不能超过 4（PMX 的限制；clothing.py 已经做了 limit_total 4）。
22. 改名后不能残留旧名顶点组；名字命中 CLOTH_RE / HAIR_RE / BREAST_RE 的具名骨，权重不应被合并掉。
23. 左右顶点数严重不对称时提示（TODO.md 记录过 肩 左右相差 2.9 倍）。

**E. 转换后的规格（以 mmd_bone_spec.md 的快速检查表为蓝本）**
24. **逐条核对付与表**：
    - 腰キャンセル → 腰，−1（不能指向 下半身）；
    - 肩C → 肩P，−1；
    - 捩1/2/3 → 主捩，0.25/0.5/0.75；
    - D 骨 → 源骨，1.0。

    写完之后还要**回读** `mmd_bone.additional_transform_bone`：mmd_tools 的 setter 在源骨不存在时会静默存入 −1（mmd_tools properties\bone.py:32-40），等于没设，而且不报错。
25. **中转结构**：apply 之后，需要中转的骨应该有 `_dummy_`（父骨 = 付与源）和 `_shadow_`（父骨 = 付与源的父骨），两者都不参与变形；对齐的骨应该是直连。
26. **IK**：
    - つま先ＩＫ 的导出目标存在，即 足首 下有带 `mmd_ik_target_override` 的子骨；
    - ひざ 有 x∈[0.5°,180°] 的限制；
    - iterations 和 ik_rotation_constraint 偏离标准值时给提示。
27. **捩骨与 D 骨**：主捩要 `enabled_fixed_axis=True`，且轴向和手臂方向一致；D 骨和捩骨要锁定位移。
28. **骨骼隐藏**：按选定的隐藏策略核对 bone.hide（付与从属骨隐藏，D 骨可见），只报告，不一刀切地修改。
