# 10b 表情（Morph）与重叠插件组调研

> 日期：2026-10-25 ｜ 本文是《10_本机已有插件工具箱.md》的附录（10b）。
> 只读调研：除本文件外没有修改或新建任何文件。每节开头给出插件根目录的绝对路径，文中 `文件:行号` 都相对于该节根目录（另有说明的除外）。
> 目标环境：Blender 3.6 + mmd_tools 1.0.2（UuuNyaa 分支）。

**结论：**
- 本机的表情代码是一条演化链：
  - `mmd_face_morphs`（09-19）：只做骨骼 morph；
  - `expression_kit`（09-27）：加入顶点 morph、AUTO，以及 DNA / ARKit / 姿势库来源；
  - `Convert_to_MMD5/expression`（10-01～10-02）：再加入 FF7 来源、MetaHuman 脸骨来源、AUTO 来源选择和手调编辑器；
  - `ff7_face_morphs`（09-26）的算法也已并入 `Convert_to_MMD5/expression/ff7.py`。
- 新插件的表情模块应以 **Convert_to_MMD5/expression + Convert_to_MMD5/convert/face.py** 为主体（ABSORB）。它已经满足"每个表情可选骨骼 morph 或顶点 morph"的决定，并按 PMX 4 权重误差逐个自动选择。另外三个表情插件都不需要单独保留。
- 最大缺口是 **XPS 命名的脸骨**：
  - 所有角色表（role table）只认三类脸骨：ROE（Rise of Eros）的三种拼写、MetaHuman `FACIAL_*`、FF7 `C_FaceBase_a`；
  - XPS 的 `head jaw`、`head lip …` 等名字只出现在 DNA 配对用的改名表里；
  - 要给角色表补 XPS 拼写，并处理"每只眼只有一根眼睑骨"的 XPS 脸。
- 重叠插件组：
  - `Tpose_change`：其中的 `bake.py`（带形态键的"姿势→rest"烘焙）、`pose.py`、`qc.py` 值得吸收；
  - `mmd_tools_helper`：腿 IK 与 mmd_tools 自己的约定有出入，只把 CSV 数据留作参考；
  - `mmd_uuunyaa_tools`：只作为可选的外部插件调用。

补充事实：
- **mmd_tools 1.0.2 里没有 `FnMorph.update_mmd_morph`**（全目录 grep 无结果）。这些插件改完 morph 后都是三步：解绑 morph slider，重建 slider，再用 `load_facial_items` 重建「表情」枠。
- 导出 PMX 时，网格上所有形态键都写成顶点 morph（Basis、`mmd_bind*`、SDEF 除外），面板和英文名取自 `vertex_morphs`。没登记的形态键归「其他」，**而且会排在 PMX morph 列表最前面**（expression_kit `mmd.py:5-10, 104-106`）。
- 模型 Build（开物理）后，导出器会把当前姿势从每个骨骼 morph 的偏移里减掉，所以**导出前必须把表情骨骼复位**（mmd_face_morphs `README.md:47-50`、`__init__.py:174-177`、`build.py:192-194`）。
- **mmd_tools 把位移全锁的骨导出为"不可移动"**。骨骼 morph 要平移的骨，必须先解开 `lock_location`（Convert_to_MMD5 `expression/mmd.py:73-91`）。
- Blender 里相连（use_connect）的骨不能平移，要平移得先断开。这只影响 Blender 内的预览和烘焙，PMX 不受影响（expression_kit `bake.py:102-120`）。
- VMD 用 15 字节 Shift-JIS 存表情名，超长或无法编码的名字永远驱动不到（expression_kit `api.py:178-190` 有此检查）。

## A1. mmd_face_morphs —— ROE 骨骼脸 → MMD 骨骼 morph

根目录：`E:\code\othercode\ripper_tpose\scripts\blender_addons\mmd_face_morphs\`

**目的**：给没有形态键、靠骨骼驱动脸的模型做 MMD 表情（Rise of Eros 每个女性角色有 32 根带蒙皮的脸骨）。流程：认脸骨 → 按配方摆骨 → 写成 PMX 骨骼 morph → 登记进「表情」显示枠 → 渲染对照图核对。

**作者 / 版本 / 日期**：ripper_tpose；`bl_info` 0.2.0，Blender 3.6（`__init__.py:8-17`）。代码日期 2026-09-19，README 2026-10-04。README 提到：从 10-04 起，ROE 批量导出默认把这些骨骼 morph 烘成同名顶点 morph，但插件本身仍只建骨骼 morph。

**依赖**：
- mmd_tools：`Model.findRoot`、`Model.armature()`、`morph_slider`、`DisplayItemQuickSetup`；
- mathutils；
- 对照图工具另需 Pillow 和 ffmpeg。

**UI**：3D 视图侧栏 → **MMD** 页签 → **Face Morphs**（`__init__.py:200-241`），从上到下：
1. 「Analyze face」按钮，下方显示拼法、脸骨数和可建表情数；
2. 设置框：眉 / 目 / 口三个开关；四个幅度倍率 Eyes / Brows / Mouth / Tongue（0.1–3.0）；「Replace same-named morphs」；
3. 「Build morphs」「Clear」两个按钮；
4. 预览框：按名字选骨骼 morph（prop_search），Weight（0–2），「Preview」「Reset」；摆着姿势时显示红字警告；
5. 报告行。

设置存放在 `Scene.mmd_face`（`__init__.py:32-51, 251`）。

| 操作符 bl_idname | 位置 | 作用 |
|---|---|---|
| `mmd_face.analyze` | `__init__.py:81-100` | 认脸骨：报告拼法、各 role 对应的骨、58 个表情里能建几个 |
| `mmd_face.build` | `__init__.py:103-130` | 先把姿势清零，再按勾选的类别建骨骼 morph（调用 `api.setup`） |
| `mmd_face.clear` | `__init__.py:133-153` | 只删本插件在这个模型上建过的 morph（记录在根对象的自定义属性 `mmd_face_morphs` 里） |
| `mmd_face.preview` | `__init__.py:156-178` | 按权重把选中的 morph 摆到骨骼上；模型已 Build 时警告导出前要 Reset |
| `mmd_face.reset` | `__init__.py:181-197` | 把所有脸骨和 morph 用到的骨复位 |

脚本入口：`api.setup(obj, categories, names, scales, replace, log)`（`api.py:28-52`），返回 morphs / skipped / face / style / unit / by_category。

**坐标系**（`faces.py:209-236`）：
- 中线：成对 role 的 x 平均值。
- 单位 `unit`：两眼间距，依次尝试 eye、upper_lid、brow 的成对骨。量不到时 `calibrated=False`，**一个 morph 也不建**（`build.py:183-191`）。
- `front`：脸骨相对头骨在 Y 方向上的符号。

**动作词汇**（`expressions.py:1-17`）：每个动作是 `(role, kind, amount)`。

| kind | 单位 | 正方向 |
|---|---|---|
| `pitch` | 度 | 骨前端向下（闭眼皮、张下巴） |
| `roll` | 度 | 外侧端向上（左右自动镜像） |
| `yaw` | 度 | 前端向外摆（中线骨朝角色左手 +X） |
| `move` | (out, fwd, up)，以眼距为单位 | out 离开中线，fwd 朝脸前 |

- 符号不靠猜：拿探针绕轴转 1°，看它是否往目标方向走（`build.py:50-54`）。
- 同一 role 上的多个旋转先在骨架空间按配方顺序合成，再一次换算到骨的局部空间（`build.py:57-106`）。
- 标定常数：`BLINK_DEG=33`、`LOWER_SHARE=0.45`、`JAW_DEG=18`（`expressions.py:19-21`）。

**配方表**：58 个，即标准 37 个（`expressions.py:119-168`）加 Tda 式补充 21 个（`:177-206`）。配方与 expression_kit 的 roles 列逐条相同，统一列在 A2 的大表里。mmd_face_morphs 和 expression_kit 的差异只有：
- `name_e` 写法不同：wink_right、wink2_right、jito、hau、troubled、smile_brow、frown、corner_up、corner_down；
- 单侧眉的 name_e 全部写成 brow_left / brow_right，彼此重复（小缺陷）；
- 没有 瞳小 和 ｷﾘｯ。

**写入 mmd_tools（build.py）**：
- `_SliderState`：先解绑 morph slider，完成后重建，原来绑定的再重新绑定（`:110-140`）。
- replace 开启时，先删除同名骨骼 morph：`mmd_root.bone_morphs.remove(index)`（`:149-159, 196-199`）。
- 新建：`morph = mmd_root.bone_morphs.add()`（**`:210`**），写入 `name / name_e / category`（`:211-213`）。
- 每根骨：`item = morph.data.add()`（**`:215`**），写入 `item.bone / item.location / item.rotation`，即 pose 空间的位移和四元数（`:216-218`）。
- 建过的名字记入根对象的 `root["mmd_face_morphs"]`（`:9, 223-224`）。
- 「表情」枠：没有就先调用 `Model(root).initialDisplayFrames(reset=False)`，然后 `DisplayItemQuickSetup.load_facial_items(root.mmd_root)`（`:162-175, 226-230`）。

**它不做顶点 morph，也不调用 shape_key_add。**

**对照图（tools/）**：
- `render_morph_sheet.py`：用法 `blender --background --python … -- <model.pmx|.blend> <out_dir> [--setup] [--size] [--lens] [--only] [--hide]`。
  - PMX 按 0.08 缩放导入（`:45-51`）；
  - 相机对准两眼中点下方 0.55 个眼距处，距离 9.5 个眼距，焦距 90，前后朝向自适应（`:98-116`）；
  - 渲染设置：EEVEE 16 采样，480×560，Standard 色彩变换，两盏日光（`:118-138`）；
  - `--hide` 按材质给面加 MASK 修改器，用来遮住挡眉的刘海（`:65-96`）；
  - 输出 `00.png`（中性）、每个 morph 一张 `NN.png`，以及 `index.json`（`:151-163`）。
- `make_sheet.py`：在系统 Python 下用 Pillow 给图加标签（日文名 30px，分类与 name_e 18px）并拼成网格（`--cols`）；可选用 ffmpeg 输出视频，每个表情停留 `--hold` 秒（`:29-69`）。

**限制**：
- 只做骨骼 morph；
- 拼写只认 ROE；
- 必须有成对的眼 / 眼皮 / 眉骨来标定；
- 导出前要 Reset；
- 幅度是在 ROE b14 上标定的。

**判定：REPLACE**。功能已被 A4 完全覆盖（A4 的 ROLES 来源输出与它逐点一致），只保留对照图的思路（见文末第 4 项）。

## A2. expression_kit —— 多来源 × 多输出的表情引擎

根目录：`E:\code\othercode\ripper_tpose\scripts\blender_addons\expression_kit\`

**目的**：一个插件统管表情，有三种输出：
- MMD 骨骼 morph；
- MMD 顶点 morph（即形态键）；
- 52 个 ARKit 形态键，注册到 Faceit，用 iPhone 面捕实时驱动。

MMD 输出还可以选 **AUTO**：逐个表情估算做成骨骼 morph 时，PMX 4 权重下会偏多少。偏得少的做骨骼 morph，偏得多的做顶点 morph。

**作者 / 版本 / 日期**：ripper_tpose；版本 0.1.0；category Animation；位于侧栏「表情」页签（`__init__.py:11-20`）。文件日期 2026-09-27。README §5 的验证环境：Blender 3.6.15 + mmd_tools 1.0.2（UuuNyaa）+ Faceit 2.3.40。

**依赖**：
- mmd_tools：可选；没有它时只能输出形态键；
- numpy、mathutils；
- Faceit：只是可选的输出目标。

**来源（sources.py）**：Faceit 不是来源，而是输出 / 注册目标（见 `faceit.py`）。

| 来源 KINDS（`:29-33`） | 类 | 形式 | 读哪一列配方 | 能输出 |
|---|---|---|---|---|
| `DNA`：MetaHuman DNA + `FACIAL_*` 骨 | `DnaSource`（`:189-234`），配对器 `DnaPoser`（`:108-186`） | pose | `metahuman`（原始控制量，经 RigLogic 求值） | 骨骼 / 顶点 / ARKit 52 |
| `SHAPES`：模型自带的 ARKit 形态键（写法不限） | `ShapeKeySource`（`:246-295`） | shape | `arkit`（Σ 权重 ×（键 − 参考键）；`?Name` 表示可选键） | 只能顶点；模型已有 ARKit 键时直接注册 |
| `POSES`：姿势库（记录的姿势 / 动作 / 姿势标记） | `PoseLibrarySource`（`:398-425`），混合用 `combine`（`:377-395`） | pose | `names`（默认取与目标同名的姿势，也可写 `{"姿势A":0.6,…}`） | 骨骼 / 顶点 / ARKit |

- **姿势的表示**：pose 来源统一用 `{bone: (location, quaternion[, scale])}`，都在 pose 空间。带缩放的姿势会强制走顶点 morph（`sources.py:44-55`；`engine.py:202-203`）。

- **DNA 关节与骨骼的配对顺序**：
  1. 同名；
  2. 忽略大小写；
  3. `unused_` 前缀；
  4. `RENAMED` 表（`FACIAL_L_Eye→head eyeball left / 左目 / 目.L`，`FACIAL_C_Jaw→head jaw`，`:92-93`）；

**引擎（engine.py）**：
- **输出方式**：
  - `BONE`：需要 pose 来源和 mmd_tools 模型；
  - `VERTEX`：任何来源都可以；
  - `AUTO`：用 `bake.WeightModel` 对超过 4 个权重的顶点做两次线性蒙皮，一次用全部权重，一次只用前 4 个。两者最大差 ≤ 阈值（默认 0.3 mm）就做骨骼 morph，否则做顶点 morph（`engine.py:111-199, 221-267`；`bake.py:136-184`）。
- **一个名字只留一种**：写骨骼 morph 前，删掉同名形态键及其 `vertex_morphs` 登记；写形态键前，删掉同名骨骼 morph（`_clear_other_kind`，`:206-218`）。
- **只删自己做的**：做过的名字以 JSON 记在网格和根对象的 `expression_kit` 标记里（`:21-55`）。
- **姿势烘成形态键（bake.py）**：
  - `RestState` 让约束静音、关闭非 Armature 修改器、其他形态键归零，退出时全部还原（`:39-99`）；
  - 逐个表情 `set_pose`，求值网格，减去静止状态，存成形态键（`engine.py:221-267`）；
  - 用网格上的**全部**权重；
  - 要平移的相连骨先断开（`bake.py:102-120`）；
  - `mm_per_unit` 猜单位：骨架高度大于 20 按厘米算，否则按米（`:129-133`）。
- **建形态键**（`engine._write_key`，`:84-96`）：
  - 没有 Basis 时先 `mesh.shape_key_add(name="Basis", from_mix=False)`；
  - `key = blocks.get(name) or mesh.shape_key_add(name=name, from_mix=False)`；
  - `key.relative_key = reference_key`；
  - `key.data.foreach_set("co", base + delta)`；
  - 滑条范围 0..1，值设为 0；
  - 小于 0.005 mm 的位移按噪声清零（`:137-138`）。

## A5. xps_to_mmd-main/doc/research_morphs.md 结论摘要

文件：`C:\…\addons\xps_to_mmd-main\doc\research_morphs.md`（259 行，2026-04-25；状态写的是"调研完成，设计文档完成，实现延后"）

**morph 体系**：
- PMX 有 5 种 morph：Group 0 / Vertex 1 / Bone 2 / UV 3 / Material 8。
- 面板编号：眉 = 1（左下）、目 = 2（左上）、口 = 3（右上）、その他 = 4（右下）。
- VMD 按日文名精确匹配，名字错一个字就不响应。

**标准表情清单与优先级**（P0 共 19 个，是最小可用集）：

| 面板 | P0 | P1 | P2 |
|---|---|---|---|
| 口 | あいうえお | ん、にやり | ▲、∧、ω、ぺろっ |
| 目 | まばたき、笑い、ウィンク、ウィンク右 | びっくり、じと目 | なごみ、はぅ、キリッ、**瞳小、瞳大** |
| 眉 | 真面目、困る、怒り、上 | 下 | にこり |
| その他 | — | — | **照れ（材质 morph）、涙（顶点 morph）** |

**四种方案的比较**：
- Path A（TPS + IDW 跨网格传输）和 Path B（KDTree 近邻传输）失败：在唇、眼睑这种薄而密的区域，跨网格对应关系不可靠。
- Path C（XPS 原生骨骼配方）失败：XPS 骨架每只眼只有一根眼睑骨。
- **Path D 成功（19/19）**：每个 morph 用模型自己的顶点组作掩码，施加预定义的毫米偏移。
  - 配方是通用的语义槽位，如 `jaw`、`lip.lower.*`；
  - 每种骨架另写约 20 个槽位的顶点组映射，如 `XPS_INASE_MAP`、`DAZ_G8_MAP`；
  - 按网格角色分配 morph：primary_face / eyelashes / eyebrow / eyeball；
  - 闭眼时让眼球后退 Y+6 mm，因为下眼睑盖不住眼球（眼球底部比眼睑低 3.2 mm）。

**教训**：
- 数据对 ≠ 视觉对，必须截图核对；
- 先探测模型能力，有 ≥ 10 个语义顶点组再尝试；
- 测试时滑块会漂移，每次要先清零；
- 目标 PMX 可能用的是骨骼 morph（Purifier Inase 的 あ 只是下巴旋转 7.5 mm）。

**未实现**：材质 morph、骨骼 morph、组合 morph、P2 表情，以及只闭一只眼时只后退对应侧的眼球。

**对新插件的意义**：
- Path D 的「顶点组权重 × 平移」，在数学上等于"只平移的骨骼 morph 经线性蒙皮烘焙"。因此可以用 A4 的 ROLES 来源（`move` 动作）加 VERTEX 输出复现它，而且还能用上旋转。
- 前提是给角色表补上 XPS 的骨名 / 顶点组拼写。
- 「眼球后退」和「按网格角色分配」值得作为新插件 ROLES 配方的补充。
