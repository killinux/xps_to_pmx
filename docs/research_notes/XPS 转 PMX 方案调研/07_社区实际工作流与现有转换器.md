# 07 社区实际工作流与现有转换器（实践者视角）

> 调研日期：2026-10-24。范围：2018–2026（Blender 2.8+ 时代）为主，但 2016–2017 的 DeviantArt 教程至今仍是英文/中文社区转载和引用的"正典"，故一并记录并标明年代。每条结论尽量标注来源日期与软件版本。工具名、日语骨骼名、标识符保持原文。GitHub 仓库的创建/最近推送日期来自 GitHub REST API（api.github.com/repos/...）元数据，于 2026-10-24 查询。

---

## 问题 1：各语言社区的"正典"工作流是什么？每一步用什么工具，哪些步骤在 Blender 做、哪些在 PMXEditor 做，为什么？

### Takeaway

三个语言社区在 2016–2026 年间收敛到同一条链路：**XPS Tools（XNALaraMesh 及其分支）把 .xps/.mesh/.mesh.ascii 导入 Blender → 用字典型插件（Hogarth-MMD 的 bones_renamer / mmd_tools_helper，或中文的 Convert to MMD 系列预设）或手工把 XPS 骨骼名改成 MMD 日文标准名 → 修层级/补骨 → mmd_tools "Convert Model" → 导出 PMX → PMXEditor 用 準標準ボーン追加プラグイン 等插件补骨、调 IK、做表情和物理 → 进 MMD 载入 VMD 测试**。Blender 负责"读取 XPS + 改名 + 重定姿势 + 导出"，PMXEditor 负责 MMD 专有的最终装配（准标准骨、物理、表情、材质、错误检查），原因是这些功能只有 PMXEditor 的插件生态能方便地做，而 XPS 文件只有 Blender 插件能读。

## 问题 2：实践者遇到的失败模式与对应修法

### Takeaway

最常见、反复出现的失败是：**骨骼名不是 MMD 日文标准名导致 VMD 不生效**；**缺 センター/グルーブ/足IK 等 XPS 根本没有的骨骼**；**XPS 多为 T 姿势而 VMD 以 A 姿势为基准导致手臂抬得过高/过低**；**材质 alpha 为 0、贴图路径/编码问题导致模型发白/透明**；**捩りボーン 軸制限 或 ローカル軸 错乱导致手臂扭曲**；**XPS 没有任何形态键，表情必须在 PE 用骨骼表情或顶点表情重做**。每一项在社区中都有成熟的修法，但都是人工步骤。

### Cited Findings

**2.1 骨骼名不匹配 → 动作不生效**

- "When you convert to pmd-format you must copy all bone names for correct work with motions data."（2016） — [Source](https://www.deviantart.com/tokami-fuko/art/Converting-XPS-to-MMD-with-bones-598167627)
- Hogarth-MMD 的字典（bones_renamer `boneMaps_renamer.py`）给出的 XPS→MMD 日文名对应表（源码逐行）：root ground→全ての親；root hips→センター；pelvis→下半身；spine lower→上半身；spine upper→上半身2；head neck lower→首；head neck upper→頭；head eyeball left/right→左目/右目；arm left shoulder 1→左肩；arm left shoulder 2→左腕；arm left elbow→左ひじ；arm left wrist→左手首；leg left thigh→左足；leg left knee→左ひざ；leg left ankle→左足首；leg left toes→左つま先；arm left finger 1a/1b/1c→左親指0/左親指１/左親指２；arm left finger 2a/2b/2c→左人指１/２/３；3a–3c→左中指１/２/３；4a–4c→左薬指１/２/３；5a–5c→左小指１/２/３（右侧同理）。 — [Source](https://raw.githubusercontent.com/Hogarth-MMD/bones_renamer/master/boneMaps_renamer.py)
- Riveda1972 的参考表亦给出 root hips→センター、pelvis→下半身、spine lower→上半身、spine upper→上半身2，并指出 XPS 中带 "*twist" 的骨 "not directly useable" 于 MMD 动画，通常应并入父骨。 — [Source](https://www.deviantart.com/riveda1972/art/MMD-XPS-to-MMD-bones-reference-list-619693351)
- XPS 导出后常出现 "Null_##" 占位名，需用 PMXE 批量改名/名称修复。 — [Source](https://www.deviantart.com/nintendraw/art/MMD-Tut-How-to-Rename-Anything-in-PMXe-and-MMD-642315757)
- 中文社区的表述："MMD 动作是按骨骼名识别而非可映射的，骨骼名要用插件改成 MMD 标准骨骼名。" — [Source](https://www.bilibili.com/video/BV1mr4y1t7Az/)（来自搜索摘要）

**2.3 T 姿势 vs A 姿势（手臂抬起/错位）**

- DanceXR 1.3.6 更新日志（2022-10-15）："Most XPS models are in T pose and VMD motion in A pose so we recommended this option [Direct Drive] to be only used on PMX models."；并提供 "Standard Pose Angle" 滑块微调手臂。 — [Source](https://stormlab.itch.io/dancexr/devlog/439796/release-136)
- 日文解释（2020-05-06）：MMD 模型手臂初始位置是 "Aスタンス"——"水平より若干下がった角度"；与动作作者所用模型角度不同时手臂会 "上や下へズレてしまいます"，"高く上がり過ぎで頭にめり込む、また逆に下過ぎて体に手がめり込む"；修法是在 MMD 中 「編集」→「ボーンフレーム位置角度補正」，算出两腕 Z 轴旋转差值后应用到全部手臂关键帧。 — [Source](https://angelia-sakuraryuusui.blogspot.com/2020/05/mmd-explaining-arm-angle.html)
- Blender 端修法（2023-01-26）：以肩为轴把腕骨绕 Y 旋转 45°，应用 Armature 修改器，"Apply as Rest Pose"；D 骨先移到别的层。 — [Source](https://pingpongfrog.com/archives/1653)
- 带形态键网格的变通（2023-09-14）：因 "モディファイアーはシェイプキーのあるメッシュには適用できない"，改用 "シェイプキーとして保存" 再替换 Basis；每臂 45°；作者警告 "肩の変形が過剰になっています"。 — [Source](https://pingpongfrog.com/archives/3055)
- PMXエディタ 端用 TransformView 把 T 改 A 作为静止姿势会引起肩部变形突出（2025-03 知恵袋提问，具体解法未在帖中给出）。 — [Source](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q14311733749)
- 一个 2026-10-08 的开源重定向项目把 MMD 标准手臂静止角写死为 `MMD_STANDARD_ARM_REST_DEGREES = 34`：上臂承担该偏移，前臂/手/手指按该偏移做共轭变换；并指出 VMD 旋转 "relative to the model's rest pose, an A-pose in MMD"。 — [Source](https://github.com/krapnikkk/retarget/issues/16)
- uitcis/Convert-to-MMD 与 Convert_to_MMD5 都把 "转换为A-Pose（T-Pose骨架转换为A-Pose）" 作为流程第一步。 — [Source](https://raw.githubusercontent.com/uitcis/Convert-to-MMD/main/README.md)
- 英文社区也有相反做法：HakunoMMD 发布 T-Pose VPD（2020-03-20），在 PMXEditor TransformView 用 "VPD-file-related → Load" 载入后保存，使模型 "can use motion data that use T-Pose"。 — [Source](https://www.deviantart.com/hakunommd/art/MMD-T-Pose-DL-Tutorial-834481783)

**2.6 手臂/膝盖扭曲、局部轴与 捩りボーン**

- ニコニコ ブロマガ（2021-06-21）：捩りボーン 的 軸制限 三个数值在 PMD/PMX 互转或使用老的 PMD 插件时会被重算成"指向原点"而损坏；自动修法：「捩りボーン軸制限修正プラグイン (PMXE)」（bowlroll.net/file/91825）；手动修法：选中捩骨 → 表示先 "<<" → 点 "軸制限" 旁的 "<" 归一化；保持捩骨为非相对且指定表示先可避免损坏。 — [Source](https://site.nicovideo.jp/ch/userblomaga_thanks/archive/ar2013830)
- nekofac（2023-01-29）：手臂乱扭四大原因：父子顺序应为 肩→腕→腕捩→ひじ→手捩→手首；捩骨位置错；ローカル軸 问题（用上述插件一键修）；捩骨已损坏——用权重目标骨替换插件把权重转回 腕/ひじ，删掉捩骨，再用準標準插件重建；"twist bones are usually the culprit"。 — [Source](https://nekofac.com/archives/1187/)
- note ig_k（2018-08-31）：骨骼 Y 轴朝侧面导致旋转方向反直觉；在 PMXe 把该骨的 "ローカル軸設定" 关掉即恢复全局朝向："OFFになっていればグローバル向きにボーンが向きますので、慣れた感じのボーンの向きになります。" — [Source](https://note.com/ig_k/n/n4716da53ab2d)
- 中文 MMD-YBK 站点有专文《PmxEditor(PE) 手臂扭曲、腿踢不直》（正文未能抓取）。 — [Source](https://mmdybk.vercel.app/PE/PE%20%E7%9A%84%E6%94%B9%E6%A8%A1%E5%AE%9E%E7%94%A8%E6%8A%80%E5%B7%A7%20&%20%E6%8F%92%E4%BB%B6%E6%8C%87%E5%8C%97%20Vol.2/)

**2.7 贴图/材质：发白、发黑、透明、颜色异常**

- mmd_tools issue #143（Hogarth-MMD 提交 2018-05-16，2019-10-19 关闭）："the Convert Model operator simply copy material's alpha to mmd_material.alpha"——当作者为了只用贴图着色而把材质 alpha 设为 0 时，Blender 中可见但导出 PMX 后不可见；修复见 commit af673da，用户应通过 mmd_tools 的 alpha 滑块而非 Blender 原生 alpha 调整。 — [Source](https://github.com/powroupi/blender_mmd_tools/issues/143)
- LearnMMD（Bandages，2016-09-01）："When I load the finished model into Miku Miku Dance it changes the base of the model to white."——贴图找不到，把原模型 texture 文件夹复制到新模型目录，PMXE 用 Edit→Update(Ctrl-U) 刷新。 — [Source](https://learnmmd.com/http:/learnmmd.com/two-pmxe-common-problems/)
- OZ-Sys（2024-10-05）：游戏提取模型的贴图常被重命名，中/日文文件名编码错误导致 MMD 找不到贴图；修法：用 Bandizip/WinRAR 指定代码页解压；在 PMXEditor 修正模型信息；文件夹/文件名与 PMX 内名称一致。 — [Source](https://www.deviantart.com/oz-sys/art/MMD-Missing-textures-or-seeing-a-white-model-1106349911)

### Inferences

- 失败模式可以按"在哪一层出错"分三类：(a) 命名层（骨名、表情名、贴图文件名编码）——几乎所有教程的第一步都在解决它；(b) 拓扑/姿势层（缺 センター/IK/準標準骨，T→A 静止姿势，捩骨轴限/局部轴）——这是手工最费时、也是自动化工具（Hogarth helper、Convert to MMD 系列、xps_to_mmd）主要竞争的地方；(c) 材质层（alpha=0、非 diffuse 贴图、材质色、DDS/编码）——多为一次性修正但极易被新手忽视而表现为"模型全白/全黑/透明"。
- T→A 的"45°"（Blender 教程）与"34°"（重定向项目）数值不一致，反映社区并没有统一的 A 姿势角度；实践者更多依赖 MMD 内的 ボーンフレーム位置角度補正 事后补偿，而不是精确对齐静止姿势。
- 中文 2017 教程把"XPS 的 twist 骨并入父骨"与"骨骼合并"放在同一集（P2 骨骼重命名及合并），与 Riveda1972 "twist 骨不可直接用于 MMD，应并入父骨"的判断一致（推断：两者都是把 XPS 的 twist 骨权重并到 腕/ひじ 后再用準標準插件重建 腕捩/手捩）。

### Gaps

- 未找到英/中/日社区对"XPS 导入后模型朝向错误或左右镜像"的直接实践者报告（仅有工具 README 中的坐标反射说明和一个重定向项目的前后镜像 issue）。
- 知恵袋 2024 年"所有骨骼都变成 IK 骨"的故障原因未被任何来源解释。
- PMXエディタ TransformView 改静止姿势导致肩部变形的具体解法未在来源中给出。
- 未找到实践者公开分享的、专门针对 XPS 的 PMXEditor 用 CSV 骨名替换表（搜索摘要提到有 QQ 文档形式的"批量重命名模板"，但无法访问核实）。

## 问题 3：现有的直接 XPS→PMX 转换器/脚本与骨名字典

### Takeaway

直接转换器确实存在且分三代：**(1) 2019 年 mariokart64n 的独立 GUI "Xnalara to MMD Converter"（v1.32，可执行名 pmxconv）**，能自动日文命名并插入 IK，但要求 xps.xps 且常出"bone name errors"；**(2) 2018–2022 年 Hogarth-MMD 的 Blender 字典插件**（bones_renamer / mmd_tools_helper，含 XNALara 列）；**(3) 2025–2026 年中文开源的新一代**：uitcis/Convert-to-MMD（预设含 xna_lara）、killinux/xps_to_mmd（拓扑识别、不依赖骨名）、killinux/Convert_to_MMD5（一键 XPS→MMD + 物理 + 表情）、SaraKale/Model-To-PMX（纯 Python，不需 Blender，仅二进制 .xps）。没有一个工具同时处理"改名 + 补骨 + IK + A 姿势 + 表情 + 物理 + 材质"并被多模型验证。

- 转换后用诊断列出缺失骨（mmd_tools_helper Armature Diagnostic）。 — [Source](https://github.com/Hogarth-MMD/mmd_tools_helper)

### Inferences

- ModDB 的 "PMX Converter v1.32"（pmxconv_v1_32.zip）与 mariokart64n 的 "Xnalara to MMD Converter v1.32" 版本号、功能描述（XPS→PMX）、关联视频（ISYab0a95iE）一致，极可能是同一程序的再上传；Steam 指南与知恵袋提到的 "pmxconv" 即此工具。此推断未获作者页面直接确认。

## 问题 4：实践者如何验证"兼容性"并判定"完成"

### Takeaway

社区的验收标准是经验式的：**在 MMD 中载入一支全身关节都会动的标准 VMD（日本社区公认的测试曲是「極楽浄土」），看手臂/腿/脚 IK 是否正常、表情能否眨眼、物理是否稀奇古怪**；更严格的作者会先跑 PMXEditor 的 PMX 错误检查并逐个预览表情。中文社区开始出现把"穿模验收"量化的工具，但尚属早期。

### Cited Findings

- うー電車（X/Twitter，2020-12-01）："Q:どうしてMMDモデルが出来上がるととりあえず極楽浄土を踊らせるの？ A:全身の関節を使った振り付けになっていて、モデルの不備を見つけやすいモーションなのでテストにはもってこいだからです。" — [Source](https://twitter.com/mokusorizm/status/1333709399580282880)（推文正文无法直接抓取，引文来自搜索结果摘要）
- Hogarth-MMD 2025 清单的"测试阶段"：运行 PMX error checker 并修正全部报错 → 用 PMX editor 的 "Morphs check button" 预览所有表情 → 在 MMD 用随机注册测试眨眼 → 载入 .vmd 舞蹈动作测试 → 用标准控件测试模型运动。 — [Source](https://www.deviantart.com/hogarth-mmd/art/Mmd-Model-Conversion-Notes-1186227547)
- rio（VRoid→MMD 博客，2022-12-08）：在 MMD 载入借来的 .vmd 播放，"無事モデルが動いていたら、動作確認終了＆VRoid製MMDモデルの出来上がりです！"；裙/袖物理被列为可选的后续改进而非验收项。 — [Source](https://rio-vroidmmd.hatenablog.com/entry/2022/12/08/001647)
- powroupi wiki 教程以"模型现在可以套 VMD 动画与 VPD 姿势"作为骨骼阶段完成的标志（并注明 lower body 骨仍无动画）。 — [Source](https://github.com/powroupi/blender_mmd_tools/wiki/Tutorial:-How-to-convert-a-3D-character-model-to-MMD)
- Convert_to_MMD5 的自动化验收：19/19 步通过、骨数 196、权重分布与参考 PMX 对照、"pose-accurate VMD playback, rotation errors ≤12°"。 — [Source](https://github.com/killinux/Convert_to_MMD5)
- Fairy0019/mmd-retarget（v0.0.2，GPL-3.0-or-later，Python 3.11 + bpy，中文文档）：针对 VMD 重定向到另一模型，提供脚锁定、手臂 IK、被动物理模拟，以及"穿模验收"——检测网格互穿并输出严重度分级、CSV/JSON 带时间标注的回归报告。 — [Source](https://github.com/Fairy0019/mmd-retarget)
- 知恵袋 2024 年的两则提问本身反映了用户层面的"验收"方式：载入动作后看脚是否跟随（足 IK 开关）、看骨骼是否全部变成 IK。 — [Source](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q12293006942)；[Source](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q12300099597)
- 中文 2017 全攻略最后一集是"人物材质和贴图修正"，即以材质在 MMD 中显示正确作为收尾。 — [Source](https://www.bilibili.com/video/BV1Dx411J7Gu/)

### Inferences

- "完成"的最低门槛在三个社区一致：模型能在 MMD 打开、套上一支舞蹈 VMD 不散架、脚 IK 跟随、能眨眼。更高门槛（PMX 错误检查零报错、表情全部预览、物理）只在资深作者（Hogarth-MMD、日本 PE 改模圈）的清单里出现。
- 「極楽浄土」被当作测试曲的理由（"全身の関節を使った振り付け"）恰好对应转换模型最容易暴露的问题：手臂静止角偏差、捩骨、足 IK、上半身2 缺失。对转换插件而言，内置一个"载入标准 VMD 并自动量化偏差"的校验器（如 Convert_to_MMD5 的 ≤12° 判据、mmd-retarget 的穿模评分）是社区正在摸索的方向。

### Gaps

- 未找到中文社区关于"用哪支动作测试新模型"的明确共识来源（搜索到的多为 極楽浄土 动作数据下载页）。
- 未找到以「ぽっぴっぽー」作为测试动作的来源。
- PMXEditor "PMXデータの状態検証"（错误检查）的具体检查项清单页面（mmd-blender fandom《PMX error checker quick reference》）被验证码拦截，未能列出检查项。

## 问题 5：2024–2026 年生态现状（Blender 版本、插件分支、PMXEditor 版本）与再分发规范

### Takeaway

2024–2026 年的实际组合是：**Blender 4.2 LTS+ 上用 Blender Extensions 平台的 MMD Tools 4.5.x（MMD-Blender/UuuNyaa 维护）+ XPS Tools 的社区分支（Valerie-Bosco/XNALara-io-Tools 支持 3.6–5.x，mayloglog 分支支持 4.4/5.0）**；Hogarth-MMD 的 helper 停更于 2021–2022、官方 Cats 于 2024 年弃坑（非官方 teamneoneko 分支转向 Blender 5），因此不少人仍保留 Blender 3.6 做转换；PMXEditor 英文版流通的是 0.2.7.3（2022）与 2024 年打包的 "0273 for Windows 11"。再分发规范方面，英文社区的主流说法是"游戏提取模型可转可分发但必须署名原作者/提取者/转换者、不得加 don't edit 之类限制、不得盈利"，部分 DeviantArt 群组直接禁止游戏提取模型；中文模之屋（aplaybox）普遍"禁止二配、禁止商用"并出现大量"XPS-MMD 自转模型配布"。
