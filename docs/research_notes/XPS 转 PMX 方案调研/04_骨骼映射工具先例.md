# 04 骨骼映射工具先例（任意角色骨架名 → 标准人形 / MMD 骨骼集）

> 调研日期：2026-10-24。本文件面向"XPS 游戏模型 → MMD PMX"Blender 插件的骨骼映射模块设计，逐一拆解现有工具的数据结构、匹配策略、剩余骨骼处理、层级修复、手动覆盖 UI、许可/维护状态，并原样抄录 XNALara/XPS 相关映射条目。所有代码/骨骼名保持原文；中文为说明。源码均来自各仓库默认分支的 raw 文件（下载后本地 grep），GitHub 元数据（许可、`pushed_at`、星数）取自 GitHub REST API 当日快照。

---

## 关键问题 0：各工具逐项档案（(i) 数据位置与格式 (ii) 匹配方式 (iii) 未匹配/多余骨骼 (iv) 层级修复 (v) 手动覆盖 UI (vi) 许可与维护 (vii) XNALara 条目）

### Takeaway
现有工具分成三类：**"大词表 + 名称归一化 + 自动修骨"**（Cats 及其 Rokoko 衍生表、VRM Add-on 的多预设评分）、**"多列对照表/预设 JSON + 用户逐槽确认"**（mmd_tools_helper 的 CSV、Convert to MMD 的 58/63 键 JSON、Expy Kit 的 Python 预设、Auto-Rig Pro 的 .bmap）、**"结构/几何推断"**（VRM Add-on 的 structure_based_mapping、MMD Tools Append 的 `detect()`、Unity Automap）。XNALara 名称在 Cats 词表、mmd_tools_helper CSV 的 `xna_lara` 列、Convert to MMD 的 `presets/xna_lara.json`、Riveda1972 的 XPS→MMD 列表中都有完整覆盖，且四者高度一致（`root hips`→センター、`spine lower`→上半身、`spine upper`→上半身2、`head neck lower`→首、`head neck upper`→頭、`arm left shoulder 1/2`→左肩/左腕、`arm left finger 1a/1b/1c`→左親指０/１/２ 等）。

- 名称标准化管线（原文）：
```python
        # List of chars to replace if they are at the start of a bone name
        starts_with = [
            ('_', ''), ('ValveBiped_', ''), ('Valvebiped_', ''), ('Bip1_', 'Bip_'), ('Bip01_', 'Bip_'),
            ('Bip001_', 'Bip_'), ('Bip01', ''), ('Bip02_', 'Bip_'), ('Character1_', ''), ('HLP_', ''),
            ('JD_', ''), ('JU_', ''), ('Armature|', ''), ('Bone_', ''), ('C_', ''), ('Cf_S_', ''),
            ('Cf_J_', ''), ('G_', ''), ('Joint_', ''), ('Def_C_', ''), ('Def_', ''), ('DEF_', ''),
            ('Chr_', ''), ('Chr_', ''), ('B_', ''),
        ]
        # List of chars to replace if they are at the end of a bone name
        ends_with = [('_Bone', ''), ('_Bn', ''), ('_Le', '_L'), ('_Ri', '_R'), ('_', ''),]
        # List of chars to replace
        replaces = [(' ', '_'), ('-', '_'), ('.', '_'), (':', '_'), ('____', '_'), ('___', '_'), ('__', '_'),
                    ('_Le_', '_L_'), ('_Ri_', '_R_'), ('LEFT', 'Left'), ('RIGHT', 'Right'),]
        # Standardize names
        for bone in armature.data.edit_bones:
            name = bone.name
            # Always uppercase at the start and after an underscore
            upper_name = ''
            for i, s in enumerate(name.split('_')):
                if i != 0:
                    upper_name += '_'
                upper_name += s[:1].upper() + s[1:]
            name = upper_name
            for replacement in replaces: name = name.replace(replacement[0], replacement[1])
            for replacement in starts_with:
                if name.startswith(replacement[0]): name = replacement[1] + name[len(replacement[0]):]
            for replacement in ends_with:
                if name.endswith(replacement[0]): name = name[:-len(replacement[0])] + replacement[1]
            # Remove digits from the start
            name_split = name.split('_')
            if len(name_split) > 1 and name_split[0].isdigit(): name = name_split[1]
            # Specific condition
            name_split = name.split('"')
            if len(name_split) > 3: name = name_split[1]
            # Another specific condition  (去掉 "Namespace:" 前缀)
            if ':' in name:
                for i, split in enumerate(name.split(':')):
                    if i == 0: name = ''
                    else: name += split
            # Remove S0 from the end
            if name[-2:] == 'S0': name = name[:-2]
            if name[-4:] == '_Jnt': name = name[:-4]
            bone.name = name
```

**(ii) 匹配算法**：
```python
BONE_NAME_LOWER_TO_UPPER_REGEX_SUB: Final = (re.compile(r"([a-z])([A-Z])"), r"\1.\2")
BONE_NAME_DIGIT_REGEX_SUB: Final = (re.compile(r"(\d+)"), r".\1.")
BONE_NAME_COMPONENT_SPLIT_REGEX: Final = re.compile(r"[-._: (){}[\]<>]+")

@cache
def _canonicalize_bone_name(bone_name: str) -> str:
    bone_name = "".join(FULLWIDTH_ASCII_TO_ASCII_MAP.get(c, c) for c in bone_name)   # 全角→半角
    bone_name = re.sub(*BONE_NAME_LOWER_TO_UPPER_REGEX_SUB, bone_name)             # camelCase 切分
    bone_name = bone_name.lower()
    bone_name = "".join(" " if c.isspace() else c for c in bone_name)
    bone_name = re.sub(*BONE_NAME_DIGIT_REGEX_SUB, bone_name).strip(".")           # 数字独立成段
    bone_name_components = re.split(BONE_NAME_COMPONENT_SPLIT_REGEX, bone_name)
    for patterns, replacement in {("l", "左"): "left", ("r", "右"): "right"}.items():
        bone_name_components = [replacement if c in patterns else c for c in bone_name_components]
    return ".".join(bone_name_components)
```
`create_human_bone_mapping(armature)` 对全部 16 个 CONFIG 调 `_match_counts`（计数：规范名归一化后与骨架中某骨相等，且该骨沿父链向上遇到的第一个已映射骨正好是规范父骨——"Validate bone ordering"），取 `(required_count, all_count)` 最大者；若 `required_count` 仍少于规范必需骨数（VRM1 为 16），再跑 `create_structure_based_mapping`，其 required 命中更多则采用，并记日志 `Treat as "%s" bone mappings`（如 "Structure Based Auto Detected"）— [human_bone_mapper.py](https://github.com/saturday06/VRM-Addon-for-Blender/blob/main/src/io_scene_vrm/common/human_bone_mapper/human_bone_mapper.py)

- XNALaraMesh 的侧别转换（XPS 名 ↔ Blender `.L/.R`）：
```python
PLACE_HOLDER = r'*side*'
RIGHT_BLENDER_SUFFIX = r'.R'; LEFT_BLENDER_SUFFIX = r'.L'
RIGHT_XPS_SUFFIX = r'right'; LEFT_XPS_SUFFIX = r'left'
def changeBoneNameToBlender(boneName, xpsSuffix, blenderSuffix):
    newName = re.sub(xpsSuffix, PLACE_HOLDER, boneName, flags=re.I)   # 'arm left elbow' -> 'arm *side* elbow'
    newName = re.sub(r'\s+', ' ', newName, flags=re.I); newName = str.strip(newName)
    if boneName != newName: newName = '{0}{1}'.format(newName, blenderSuffix)  # -> 'arm *side* elbow.L'
    return newName.strip()
```

### Inferences
- 四条独立来源（Cats 词表、mmd_tools_helper CSV、Convert to MMD JSON、Riveda 列表）对 XPS "标准"名的解释完全一致（Convert to MMD 只在 `spine lower` 归 下半身/上半身 上与其余三者不同，且该差异源于其 JSON 保留了 `lower_body_bone` 却把 `upper_body_bone` 留空），说明 XPS 社区名虽无官方规范，但 Padme4000 列表派生的这套名字足够稳定，可以作为插件的"XPS 预设"直接硬编码。

- Cats 的词表是"归一化后的形态"，而 mmd_tools_helper/Convert to MMD/Riveda 存的是"原始形态"；两种设计分别适配"模糊自动匹配"和"精确预设"。XPS 名带空格与数字（`arm left finger 1a`），Cats 规则 `' '→'_'` + 首字母大写后变成 `Arm_Left_Finger_1a`，与其词表条目吻合，证明 Cats 对 XPS 的支持是经过实测的。
- Rokoko 的 `bones.py` 与 Cats 的 `bone_rename` 高度同源（连注释都相同），但 Rokoko 以 LGPL-3.0 发布、Cats 以 MIT 发布；二者可视为同一词表的两个许可副本。

### Gaps
- Auto-Rig Pro `.bmap` 文件的内部格式：官方文档只说明可 import/export，未公开结构；商业插件源码不可获取，未能核实其"按名称猜测"算法细节。

## 关键问题 2：各工具收敛到的规范人形骨骼 ID 集合，以及可选骨（UpperChest/Toes/Eyes/Shoulder）缺失时的表示

### Takeaway
所有工具都收敛到 Unity `HumanBodyBones`/VRM 1.0 的 55 骨人形集：`Hips, Spine, Chest, UpperChest, Neck, Head, L/R Eye, Jaw, L/R Shoulder, UpperArm, LowerArm, Hand, UpperLeg, LowerLeg, Foot, Toes, 5 指×3 节`；MMD 工具在此之上再加 MMD 特有控制骨（`全ての親/センター/グルーブ/腰/操作中心/足ＩＫ/つま先ＩＫ/足IK親/肩P/肩C/腕捩/手捩/足D/足先EX/両目`）。可选骨的表示方式有四种：空字符串占位（Convert to MMD JSON、mmd_tools_helper CSV 空单元格、Expy Kit `''`/`None`）、规范表中的 `requirement`/`parent_requirement` 布尔（VRM Add-on）、"缺失就造/多余就并"（Cats 对 Chest/Neck/Upper Chest）、以及 `MMDBoneType` 分类 + `exist_bone_types` 集合（UuuNyaa）。

### Cited Findings
- Unity：55 个 `HumanBodyBones` + `LastBone`；"required (solid circles) and which are optional (dotted circles)"；可选骨 "can have their movements interpolated automatically"（2017.4 文档语） — [HumanBodyBones](https://docs.unity3d.com/ScriptReference/HumanBodyBones.html)；[class-Avatar](https://docs.unity3d.com/Manual/class-Avatar.html)；[ConfiguringtheAvatar 2017.4](https://docs.unity3d.com/2017.4/Documentation/Manual/ConfiguringtheAvatar.html)
- VRM 1.0：必需 16 骨（hips, spine, head, 左右 upperArm/lowerArm/hand/upperLeg/lowerLeg/foot），`chest/upperChest/neck/shoulder/toes/eyes/jaw/手指` 可选，但 "upperChest can exist only when chest exists"、"The parent bone of the humanoid bone is fixed"、"It is permissible to have non-humanoid bone nodes between humanoid bones"；0.x 中 chest/neck 为必需 — [humanoid.md](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_vrm-1.0/humanoid.md)
- VRM Add-on 用 `HumanBoneSpecification(requirement: bool, parent_requirement: bool, parent_name)` 建模；`HumanBoneName` 枚举值 `hips, spine, chest, upperChest, neck, head, leftEye, rightEye, jaw, leftUpperLeg … rightLittleDistal`；候选过滤保证层级一致 — [vrm1/human_bone.py](https://github.com/saturday06/VRM-Addon-for-Blender/blob/main/src/io_scene_vrm/common/vrm1/human_bone.py)；[editor/property_group.py](https://github.com/saturday06/VRM-Addon-for-Blender/blob/main/src/io_scene_vrm/editor/property_group.py)
- Cats 规范名集合即 `dont_delete_these_main_bones`（`Hips, Spine, Chest, Upper Chest, Neck, Head, Left leg/knee/ankle/toe, …, Left shoulder/arm/elbow/wrist, …, LeftEye/RightEye/Eye_L/Eye_R, Left leg 2/Right leg 2, Thumb0_L…LittleFinger3_R`，另 `Breast_L/R`）；`bone_list_parenting` 规定 `'Neck': 'Upper Chest'`、`'Left shoulder': 'Upper Chest'`，但运行时 "if value == 'Upper Chest' and 'Upper Chest' not in armature.data.edit_bones: value = 'Chest'"；缺 Chest 时新建、缺 Neck 时新建、Upper Chest 默认并入 Chest — [armature_bones.py#L34-L150](https://github.com/absolute-quantum/cats-blender-plugin/blob/master/tools/armature_bones.py)；[armature.py#L770-L852、#L1156-L1178](https://github.com/absolute-quantum/cats-blender-plugin/blob/master/tools/armature.py)
- Expy Kit：`HumanSpine(head, neck, spine2, spine1, spine, hips)` + `root`、`HumanArm(shoulder, arm, forearm, hand)` + `arm_twist/arm_twist_02/forearm_twist/forearm_twist_02 = None`、`HumanLeg(upleg, leg, foot, toe)` + twist 字段、`HumanFingers` 每指 `[a, b, c, meta]`、`SimpleFace(jaw, left_eye, right_eye)`；缺失即 `''`，`conversion_map` 遇空名跳过（`if not bone_name: return`）— [bone_mapping.py](https://github.com/pKrime/Expy-Kit/blob/main/rig_mapping/bone_mapping.py)

- Riveda 列表把 XPS 的 `spine lower b`/`spine upper b` 映射到非标准的 `上半身b`/`上半身3`，并标注这些及 `親指０` "Many mmd models don't have them" — [DeviantArt](https://www.deviantart.com/riveda1972/art/MMD-XPS-to-MMD-bones-reference-list-619693351)

### Inferences
- 面向 PMX 的插件应采用"VRM/Unity 55 骨 ID 作内部规范 + MMD 日/英名作输出层"的双层模型：内部 ID 稳定（便于复用 VRM Add-on 的 12 张体系表与结构搜索），输出层再决定 `Chest→上半身2`、`UpperChest→上半身3 或并入上半身2`、`Hips→下半身 并另造 センター`、`Toes→足先EX 或 つま先` 等 MMD 特有决策。
- 可选骨的最佳表示是 VRM 式 `requirement + parent_requirement + 固定父骨`：它既能驱动 UI（必需/可选分组、候选过滤），又能在结构搜索里作为评分依据；Convert to MMD 的"空串"方式简单但无法表达"父骨缺失时怎样回落"（Cats 用硬编码 `Upper Chest→Chest` 回落）。
- MMD 拇指的 `親指０` 对应 Unity `ThumbProximal`/VRM `ThumbMetacarpal`，而 XPS 的 `finger 1a` 正是这一节；三节都齐的 XPS 模型可直接产出 MMD 准标准的 親指０，缺 `1a` 的模型才需要 VRM 式"候选下移"。

### Gaps
- 未找到 Unity 官方页面明文列出 15 根必需骨的清单（文档只给 `HumanTrait.RequiredBone()` API 与"实心/虚线圆"说明），必需集只能由 VRM 1.0 表与 Unity 行为间接推断。
- MMD 侧"准标准骨"（準標準ボーン）官方定义未在本次调研中直接引用，仅通过 UuuNyaa 的 `MMDBoneType` 枚举与 mmd_tools_helper 的注释间接获取。

## 关键问题 3：哪些匹配策略稳健（归一化管线、词元同义、结构回退），以及工具如何呈现映射供手工修正

### Takeaway
稳健度最高的组合是 VRM Add-on 的三段式：**归一化（全角→半角、camelCase 切分、小写、数字独立、分隔符统一、`l/r/左/右`→`left/right`）→ 多预设评分（按"必需骨命中数 + 父链一致性"选最优体系）→ 结构搜索回退（归一化坐标 + 必需骨 1000 分/可选骨 20 分的分支搜索）**；Cats/Rokoko 的"大词表 + 大小写不敏感 + `\L` 侧别通配 + 上下文冲突表"覆盖面最大但不可解释；UuuNyaa `detect()` 的"手指计数找手→父链找臂→公共祖先找胸→最低点找脚趾"几何法对无名可依的拆包骨架最有用。UI 上所有可手改的工具都用 Blender `prop_search` 逐槽选骨，差别在于：是否按左右/手指分列（Convert to MMD、Expy Kit、UuuNyaa）、是否过滤候选（VRM）、是否有"取当前选中骨"按钮（Convert to MMD、Expy Kit）、预设格式（JSON / Python / 两列 UIList + JSON 学习表）。

## 关键问题 4：工具如何处置剩余骨骼（twist/roll/helper/IK/武器/布料）

### Takeaway
三种策略并存：**并权重后删除**（Cats 的 `bone_reweigth_to_parent`/`bone_reweight`/`fix_twist_bones`、mmd_tools_helper `combine_2_bones`、Convert to MMD 上游的"合并链/合并所选权重"、UuuNyaa `add_leg_ik` 的 `dissolve_bone`）、**按权重有无删骨/隐藏**（Cats `delete_zero_weight`+白名单、Convert to MMD `clear_unweighted_bones`、XNALaraMesh 把 `unused*` 与无顶点组链移到隐藏层）、**保留原名不处理并分组**（mmd_tools_helper/Expy Kit/Rokoko/VRM 对未映射骨不动；Convert to MMD 把未归组骨放入 `other` 集合、把 `_dummy_/_shadow_` 捩骨放入隐藏 `mmd_dummy` 集合）。MMD 特有辅助骨（IK、`_dummy_`、`_shadow_`、ShoulderP、WaistCancel、LegIKParent）在转向 VRChat 的 Cats 中被整体删除/并入父骨，而转向 MMD 的工具则反过来生成它们。

### Inferences
- 对 XPS→PMX：XPS 模型常见的 `unused*`（无权重占位骨）、`*twist*`/`*adj*`（辅助变形骨）、武器/头发/裙骨（有权重但非人形）应分别处理——`unused` 直接删（mmd_tools_helper/XNALaraMesh 先例）；twist/adj 并入父骨（Cats `bone_reweigth_to_parent` + Riveda 建议）；有权重的非人形骨保留原名、挂到最近的人形父骨并放入 "その他/other" 显示框（Convert to MMD 先例），以便后续作为物理骨。
- Cats 的 `fix_twist_bones` 比例分配（0.25/0.5/0.75）说明"把多段 twist 并回单骨"会损失扭转分布，若目标 PMX 想保留 MMD 准标准 `腕捩/手捩`，更好的做法是像 Convert to MMD 上游 `add_twist_bone` 那样把 XPS 的 twist 权重重新映射到 `腕捩1/2/3`。
- "零权重即删"必须配白名单：MMD 控制骨（`全ての親/センター/IK`）天然无权重，Convert to MMD 本地版未加白名单会误删，上游已修正。

- Cats `fix_twist_bones` 的比例常数来源未在源码注释中说明。
