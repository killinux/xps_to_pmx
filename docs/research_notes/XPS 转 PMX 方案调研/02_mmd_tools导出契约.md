## Q1. 模型结构：Root Empty / Armature / Mesh / 刚体 / Joint 的组织方式，`Model` 类如何查找与创建，`mmd_tools.convert_to_mmd_model` 做了什么

### Takeaway
一个可被 mmd_tools 导出的模型 = 一个 `mmd_type == "ROOT"` 的 Empty（挂 `mmd_root` 属性组）→ 其**第一个 ARMATURE 子对象**作为骨架 → 骨架的**递归子对象中 `type == "MESH"` 且 `mmd_type == "NONE"`** 的对象作为网格；刚体/Joint 分别挂在 root 下名为 `rigidbodies`/`joints` 的分组 Empty（`mmd_type` 为 `RIGID_GRP_OBJ`/`JOINT_GRP_OBJ`）之下。`Model.create()` 一步建好 root+armature，`mmd_tools.convert_to_mmd_model` 能把任意骨架+网格"收编"为 MMD 模型，但**不会**填写骨骼的日文名/bone_id/IK/刚体等 MMD 专有数据。

### Inferences
- 转换器可直接调用 `Model.create(name, name_e, scale, obj_name, armature_object=xps_armature)` 完成 root/骨架收编，再用 `FnModel.attach_mesh_objects(root, meshes, add_armature_modifier=True)` 挂网格；这比手工设置 `mmd_type`/`mmd_root` 更稳妥（它还会创建 `mmd_shadow`/`mmd_dummy` 骨骼集合——付与亲功能依赖它们，见 Q10 的 issue #340）。
- "Convert Model" 对我们只有材质/形态键登记的价值；骨骼名、bone_id、IK、刚体仍需转换器自己写入。
- **最小导出契约清单**（综合 Q1–Q9）：① root Empty `mmd_type="ROOT"`，`mmd_root.name` 非空；② root 下恰有一个 ARMATURE 子对象，网格为其（递归）子对象且 `mmd_type="NONE"`、在当前 view layer 中、非空；③ 顶点组名 = **Blender 骨骼名**（不是 `name_j`）；④ 每个 pose bone 填 `mmd_bone.name_j/name_e/bone_id`（或导出前跑 `fix_bone_order`）；⑤ 形态键第 0 个为 Basis；⑥ 材质填 `mmd_material.*`，贴图节点命名 `mmd_base_tex`/`mmd_sphere_tex`，toon 用 `is_shared_toon_texture`+`shared_toon_texture` 或 `toon_texture` 路径；⑦ 刚体/Joint 走 `FnRigidBody.new_*_object`+`setup_*_object`；⑧ `display_item_frames` 至少含 `Root`/`表情`（`initalize_display_item_frames`）；⑨ 导出前模型处于未 build 状态（`is_built=False`），骨架位于 rest pose。

### Gaps
- 任务提到的 root 上"active toon"属性在 v4.5.5 源码中不存在（toon 是材质级属性）。
- `Object.children` 的遍历顺序决定 `iterate_mesh_objects` 的原始顺序，但导出器随后按对象名重新排序（见 Q4），因此该顺序对导出无影响；未进一步验证 Blender 内部 `children` 的排序规则。

## Q2. 骨骼属性（`mmd_bone`）、Bone Order 面板、变形阶层、付与亲、固定轴/局部轴、表示先、影子骨与 MMD 约束

### Takeaway
PMX 骨骼的几乎全部字段来自 `PoseBone.mmd_bone`（`MMDBone`）；导出顺序 = `bone_id` 升序（-1 排最后、同值按名），`mmd_tools.fix_bone_order` 会按"父在子前、付与亲在被付与者前（仅在 `transform_after_dynamics`/`transform_order` 相同时）"重排并压实 ID。付与亲（Rotate+/Move+）在 Blender 侧由名为 `mmd_additional_rotation`/`mmd_additional_location` 的 TRANSFORM 约束 + `_dummy_*`/`_shadow_*` 影子骨实现，导出时跳过影子骨（`is_mmd_shadow_bone`）。

### Inferences
- 转换器导出前需保证：骨架对象与 root 的世界矩阵为单位（`Model.create` 已把骨架矩阵转移到 root；网格使用自身 `matrix_world`，若 XPS 导入时有旋转/缩放会被烘焙进 PMX，但骨骼轴向量的 `__to_pmx_axis` 使用 `pmx_matrix_rot`（含骨架世界旋转），两者一致），且所有对象 scale 为正（负缩放会额外反转面绕序）。
- XPS 模型若导入时以 Z-up、面朝 -Y 放置（常见的 XPS 导入器行为），无需额外旋转即可用 mmd_tools 导出；比例上以 `scale=12.5` 为默认（1 Blender 单位 = 12.5 PMX 单位，PMX 中 1 单位 ≈ 8cm），XPS 单位需先归一到米。

### Inferences
- MMD Tools Append 的 `HUMANOID_DEFAULTS` + `MMDBoneInfo` 是现成的"英文人形骨名 → MMD 日文名"参考表，可作为 XPS 骨名映射的基线（XPS 常见骨名如 `head neck lower`/`arm left shoulder 1`/`leg left thigh` 等仍需自建别名表）；其 `HumanoidEditor.add_leg_ik`/`add_eyes_bone` 的实现是生成 足ＩＫ/つま先ＩＫ/両目 的可参考样例（细节未抓取，见 Gaps）。
- 由于 mmd_tools 是 GPL-3.0-or-later，且我们的插件会 `import` 其模块并调用其 API（构成组合作品），转换插件应以 GPL-3.0-or-later（或兼容许可）发布；若只通过 `bpy.ops.mmd_tools.*` 调用操作符而不 import 模块，法律边界更模糊，但在 extensions.blender.org 上无论如何都必须整体 GPL 兼容。
- 4.5.6+ 的 "Texture Relative Path" 与 "auto texture relative path depth" 选项、4.5.14 的材质排序说明导出 API 参数在持续变化：转换器调用 `pmx_exporter.export(**kwargs)` 时应只传本版本存在的参数或做版本分支；也应检测 `MMD_TOOLS_VERSION`。
- v4.5.13 起 OpenCC 以 wheel 形式提供，`from ..externals.opencc import OpenCC` 这类内部路径可能已变——不要依赖 mmd_tools 的 `externals`。

## Q11. 另一个插件如何程序化调用 mmd_tools：操作符 id、模块导入路径、版本检测与陷阱

### Takeaway
推荐两条路径并存：(a) 通过 `bpy.ops.mmd_tools.*` 调用操作符（需要正确的 context：活动/选中对象属于目标模型，OBJECT 模式）；(b) 动态定位包名（`bl_ext.user_default.mmd_tools` / `bl_ext.blender_org.mmd_tools` / 旧版 `mmd_tools`）后 `importlib.import_module` 其 `core.*` 模块（`Model`、`FnModel`、`FnBone`、`FnMaterial`、`FnRigidBody`、`core.pmx.exporter.export`）。版本用包内常量 `MMD_TOOLS_VERSION`（读自 manifest）判断。`core/pmx/__init__.py` 是一个**不依赖 bpy** 的纯 Python PMX 读写器，可作为兜底方案直接构造 `pmx.Model` 写文件。

### Inferences
- 包定位代码建议：遍历 `("bl_ext.blender_org.mmd_tools", "bl_ext.user_default.mmd_tools", "mmd_tools")` 以及 `[k for k in bpy.context.preferences.addons.keys() if k.endswith("mmd_tools")]`，用 `importlib.import_module` 导入成功者；再读 `module.MMD_TOOLS_VERSION`（字符串 "4.5.5"）做版本门槛（例如要求 ≥4.5，以保证 `bone_id`/`display_connection_*` 方案存在，这些在 2025-04 的 PR #205 后才稳定）。
- 调用 `bpy.ops.mmd_tools.export_pmx(filepath=...)` 前：`bpy.ops.object.mode_set(mode="OBJECT")`，选中并激活 root（或模型内任一对象），确保所有网格在当前 view layer 可见/未排除；或直接调用 `pmx_exporter.export(...)`，并自行 `FnModel.realign_bone_ids` 后传 `fix_bone_order=False` 以避免对 context 的依赖。
- 若未来 mmd_tools API 变化过大，仍可保留 "构造 `pmx.Model` → `pmx.save`" 的后备路径：它只需本调研记录的数据契约与坐标换算，不依赖 Blender 属性组。
- 不要 `import` mmd_tools 的 `externals`（4.5.13 后改为 wheel），也不要依赖 `properties/__init__.py` 的内部行为。
