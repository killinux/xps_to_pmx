## 问题 1：材质与贴图（贴图格式 / toon / sphere / 边线 / 绘制顺序 / XPS 渲染组映射 / 材质モーフ开关）

### Takeaway
MMD 原生材质只消费 1 张漫反射贴图 + 可选 sphere 贴图 + toon 贴图（PMX 规范），游戏模型的法线/高光/遮罩/自发光贴图在 PMX 里**没有原生槽位**；社区默认是"皮肤 toon02（或 04/05）、其余 toon01/03，sphere 多为关闭或加算，边线全模型统一粗细并在透明/碎片材质上关闭"。MMD 严格按材质列表顺序绘制，且"半透明材质之后绘制的东西不会被它透过"，所以透明材质必须排在被它遮挡的材质之后，脸部件顺序惯例为 アイライン→眉→瞳→高光；XPS 的 `rgAlpha` 渲染组可直接作为"透明材质、后排、关边线"的判定依据。材质开关用 材質モーフ：初始可见的用 乗算×0 隐藏，初始隐藏（alpha=0）的用 加算+1 显示，并把隐藏材质的边线 alpha 置 0。

### Cited Findings

#### 1a. 贴图格式与路径
- 【硬性】MMD 可读取的贴图格式：BMP、JPG（Ver.5.17 以降）、PNG（Ver.6.00 以降，含透明信息）、TGA（含透明）、DDS（含透明）、HDR；附件（アクセサリ）透明需 32bit TGA，或 Ver.6 以后 32bit PNG — [VPVP wiki「MikuMikuDance/拡張子」](https://w.atwiki.jp/vpvpwiki/pages/322.html)（搜索摘要；页面本体被反爬拦截，未能全文核对）
- "MMD can use PNG, JPG, BMP, and TGA formats (and maybe more)"；评论区补充 MMD 也支持 .dds；.sph/.spa "are just regular image files. The extensions are only there to tell how the image was meant to be used"，"MMD doesn't care what the file extension is"；alpha 255(=1.0) 完全不透明、0 完全不可见 — [LearnMMD: Everything you never wanted to know about textures](https://learnmmd.com/http:/learnmmd.com/know-about-pmd-pmx-textures/)
- sphere 贴图建议 256×256；MMD 自带 metal.sph；任意图片改扩展名即可成为 .sph/.spa — [LearnMMD: .SPH and .SPA Files](https://learnmmd.com/http:/learnmmd.com/pmd-editor-basics-sph-and-spa-files-add-sparkle/)
- 【冲突】LearnMMD 某教程称 "TGA files do not use transparency, so if you save it as that file-type, it won't work"，建议存 PNG — [LearnMMD: Using Texture Transparency](https://learnmmd.com/http:/learnmmd.com/using-texture-transparency-hides-mmd-model-problem-areas/)；与 VPVP wiki "32bit TGA 可带透明" 相矛盾，推测该作者导出的是 24bit TGA。
- 【硬性】toon 文件名 toon01.bmp～toon10.bmp 为保留名："If you use these names for your toons, MMD will ignore your files and use its own"；"Toons have to be .bmp files"；toon 图左侧边缘用于非自阴影材质、右下角用于开启自阴影时 — LearnMMD 搜索摘要（出处为 LearnMMD 站内教程，疑为 [Mae Blythe《Make a Model Part 24》](https://learnmmd.com/Make-Your-First-Model-Using-Blender-by-Mae-Blythe/Make-a-Model-Part-24/index.html)，未逐页核对）
- 【硬性】PMX 材质的 toon 引用：toon reference flag "0 = Texture reference, 1 = internal reference"（内建 toon01～toon10）；sphere 混合模式 "0 = disabled, 1 = multiply, 2 = additive, 3 = additional vec4"；面数 "always be a multiple of 3" — [PMX 2.0 规范（英译 gist）](https://gist.github.com/felixjones/f8a06bd48f9da9a4539f)
- mmd_tools 的共享 toon 以 0～9 整数表示 "(toon01.bmp ~ toon10.bmp)"，`is_shared_toon_texture` 默认 False、`shared_toon_texture` 默认 0 — [mmd_tools/properties/material.py](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/mmd_tools/properties/material.py)
- 路径陷阱：日文文件名经不支持 Unicode 的解压工具会变成乱码，导致"白模"（贴图丢失）；建议 Bandizip 设日文代码页或切换系统区域 — [LearnMMD: Downloading Japanese Models Can Scramble File Names](https://learnmmd.com/http:/learnmmd.com/downloading-japanese-models-can-scramble-file-names/)
- PMXE 导入他模型后贴图路径丢失→白模；修法是把贴图复制到目标模型目录并 Ctrl+U 刷新 — [LearnMMD: PMXE Common Problems](https://learnmmd.com/http:/learnmmd.com/two-pmxe-common-problems/)
- Nuthouse01 的总体清理会用 shift_jis 编码检查"完整文件路径、模型日文名、启用的骨骼名、非隐藏モーフ名"，任何不可编码字符都报告（`find_shiftjis_unsupported_names`）；并检查 shift_jis 字节长 >15 的骨骼/モーフ名（"will not be successfully saved/loaded with VMD files"） — [model_overall_cleanup.py](https://github.com/Nuthouse01/PMX-VMD-Scripting-Tools/blob/master/mmd_scripting/scripts_for_gui/model_overall_cleanup.py)
- mmd_tools `mmd_tools.validate_textures`：检查贴图文件缺失、"Different textures with same path"、"Texture filename conflict"、文件名主干含"additional unallowed characters"；`mmd_tools.fix_texture_issues` 会把缺失的 toon 贴图回退到共享 toon（"Using shared toon{NN}.bmp"，无法判断时 toon01.bmp）、统一同路径贴图名、为重名贴图改名并复制文件、删除无文件的 image block — [mmd_tools/operators/model_validation.py](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/mmd_tools/operators/model_validation.py)
- mmd_tools 导出时对贴图相对路径执行 `re.sub(r'[:*?"<>|]', "", ...)`、`os.path.normpath` 并统一为 "/"；相对路径为空时按 `auto_texture_rel_path_depth` 自动取目录尾部若干级 + 文件名；`copy_textures_mode` 支持 NONE / SKIP_EXISTING / OVERWRITE — [mmd_tools/core/pmx/exporter.py](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/mmd_tools/core/pmx/exporter.py)
- Nuthouse01 `file_sort_textures`："sort the tex/spheremap/toon files used by a model into folders for each category"，未使用的图片移到 "unused" 文件夹，列出 PMX 引用但磁盘不存在的文件，并先做 zip 备份 — [file_sort_textures.py](https://github.com/Nuthouse01/PMX-VMD-Scripting-Tools/blob/master/mmd_scripting/scripts_for_gui/file_sort_textures.py)

#### 1c. sphere（スフィア）
- 模式含义：乗算（变暗）、加算（.spa，环境光/高光感）、サブテクスチャ（少用） — [LearnMMD: Understanding PMXE Materials](https://learnmmd.com/http:/learnmmd.com/understanding-pmxe-materials/)
- 实测分布："ほとんどの場合、「無効」または「加算スフィア」でした"；推荐头发/眼睛用加算模拟反光，金属用高光 — [pingpongfrog【PmxEditor】Toon & Sphere](https://pingpongfrog.com/archives/1869)
- サブテクスチャ使用第二套 UV（AddUV）相乘到基础贴图；MME bug："doesn't actually know whether to use add blending or multiply blending for subtexture"，需把**前一个材质**的 sphere 模式设为乘算 — [LearnMMD: Subtexture](https://learnmmd.com/http:/learnmmd.com/subtexture/)
- vroid2pmx：VRM 材质含 `_SphereAdd` 时 `sphere_mode = 2`（加算），并额外生成头发艶 sphere（"髪の毛の艶（スフィア）作成"） — [VroidExportService.py](https://github.com/miu200521358/vroid2pmx/blob/main/src/service/VroidExportService.py)、[vroid2pmx Readme.txt](https://github.com/miu200521358/vroid2pmx/blob/main/%E9%85%8D%E5%B8%83/v2.1.5/Readme.txt)

#### 1d. 边线（エッジ）、両面描画、阴影标志
- 【硬性】PMX 绘制标志位：bit0 No-cull（两面）、bit1 Ground shadow、bit2 Draw shadow（写自阴影贴图）、bit3 Receive shadow、bit4 Has edge；边线色 RGBA + 边线尺寸 float — [PMX 2.0 规范](https://gist.github.com/felixjones/f8a06bd48f9da9a4539f)
- 边线三要素：按材质开关、颜色、尺寸；MMD 内显示粗细 = "元のモデルのエッジの太さ×数値"；作者实例 "うちのモデルは基本0.3～0.4、歯などの細かいところは0.2"；边线 A 值为透明度，调低也会影响地面影 — [ブロマガ: MMDのエッジ（輪郭線）について](https://site.nicovideo.jp/ch/userblomaga_thanks/archive/ar1361050)
- 不想要边线时 "don't just reduce the alpha to 0... Instead, reduce the thickness to 0"；"2-sided materials don't shadow properly, and some effects look very wrong"，且影响帧率；地面影 "really troublesome, and you should probably disable it in MMD anyways"，天空盒/窗户关 Shad/Grnd Shad — [LearnMMD: Understanding PMXE Materials](https://learnmmd.com/http:/learnmmd.com/understanding-pmxe-materials/)
- 全模型边线粗细 "基本は全て統一"；边线与贴图颜色冲突处用 UV 编辑器插件把顶点边线倍率设 0；セルフ影（self shadow）常对脸部材质关闭以免前发在脸上投硬阴影；地面影保持开启；セルフ影マップ极少关闭 — [雪梨: VRoidからのMMDモデル作成(3-4)](https://note.com/strmy/n/n8096e20a3244)
- 睫毛末端、白目被盖住部分：选中顶点把エッジ倍率设 0 即可消除多余边线 — 搜索摘要（[うさこのブログ UV展開（目、顔）](https://usausakokoko.hatenablog.com/entry/2018/09/11/064414)，未全文核对）
- KKPMX 手工最低步骤："Tick off 'Edge (Outline)' for Materials with excessive amount of alpha texture (or lots of corners)"；被禁用材质置 `alpha=0, edgesize=0, flaglist[4]=False` — [KKPMX Readme](https://github.com/CazzoPMX/KKPMX/blob/master/Readme.md)、[kkpmx_core.py](https://github.com/CazzoPMX/KKPMX/blob/master/src/kkpmx_core.py)
- vroid2pmx 的边线策略：默认标志 `0x02|0x04|0x08`（地面影+自阴影贴图+自阴影），VRM `doubleSided` 时加 `0x01`；注释 "エッジ描画は透明ポリの裏面がエッジ色で塗りつぶされてしまうので、ここでフラグはONにしない"，仅对 `_Body_/_Face_/_Hair_/Accessory` 且 edge_size>0 开边线，衣物类 MASK/BLEND 材质需结合贴图 alpha 判断；并生成 "エッジOFF" 材质モーフ — [VroidExportService.py](https://github.com/miu200521358/vroid2pmx/blob/main/src/service/VroidExportService.py)、[Readme.txt](https://github.com/miu200521358/vroid2pmx/blob/main/%E9%85%8D%E5%B8%83/v2.1.5/Readme.txt)
- "shadowy material" 反模式：材质 alpha==0 但边线开启且 edgealpha≠0、edgesize≠0 会在 MMD 中残留边线影子，Nuthouse01 单独检测（`find_shadowy_materials`） — [model_overall_cleanup.py](https://github.com/Nuthouse01/PMX-VMD-Scripting-Tools/blob/master/mmd_scripting/scripts_for_gui/model_overall_cleanup.py)

#### 1e. 绘制顺序与透明
- 【硬性】"１つのモデルの中では材質ごとに、材質順に描画されます"；多物体应 "奥にあるもの→→手前にあるもの、という順で描画する"；透明材质应最后绘制，否则后绘制的不透明物体会盖住透明处；模型与附件不能交错（附件1→模型全部→附件2…），在「背景」→「アクセサリ編集」及「モデル描画順」调整 — [ブロマガ【Tips】モデルやアクセサリの描画順について](https://site.nicovideo.jp/ch/userblomaga_thanks/archive/ar234462)
- 【硬性】MMD 规格：「半透明素材の後に描写するものは、半透明素材に透過させない」；口诀「穴をあけるものは後！」 — [MMDSupporter vol.2『透明板ポリによる描画順マジック』](https://note.com/mmd_supporter/n/n594976ba8d33)
- 透明材质故障的典型原因："描画順が先の物（29）よりカメラ視点で見て奥に描写順が後のもの（30）が配置されている"，解法是把前面的板ポリ拆成新材质 31；"透過素材使用時はカメラの回転にとても弱くなる" — [MMDSupporter Q&A『透過素材トラブル』](https://note.com/mmd_supporter/n/n3c6a3f89843a)
- 双层半透明布料（面纱）：复制面并翻转法线分成"裏/表"两材质，顺序 "上の裏→下の裏→下の表→上の表"，"裏が先、表が後の描画になるようにしました" — [雪梨: 綺麗に透けるヴェールの作り方](https://note.com/strmy/n/n0d098a7660e7)
- 脸部件顺序惯例："顔のパーツは必ず以下の順番にしています"：アイライン → 眉毛 → 瞳 → 目のハイライト；透明材质整体下移 — [rio-vroidmmd: PMXエディタでの作業](https://rio-vroidmmd.hatenablog.com/entry/2021/11/15/105821)
- MMD 内对附件可用 Draw Order 调整，PMD/PMX 模型内部问题需在 PMDE/PMXE 改材质 — [LearnMMD: Make Transparent Parts Work Correctly](https://learnmmd.com/http:/learnmmd.com/make-transparent-parts-work-correctly/)
- 自动判定透明/不透明的局限："determining whether a material is opaque or translucent is impossible for an algorithm to do perfectly" — [babylon-mmd issue #22](https://github.com/noname0310/babylon-mmd/issues/22)
- 根据贴图 alpha 删除不可见面：KKPMX 以 `alphaThreshold = 10`（0～255）判断像素不可见，"An face is invisible if the corresponding texture pixel(== UV) of all three vertices has an alpha value of 0%" — [kkpmx_core.py](https://github.com/CazzoPMX/KKPMX/blob/master/src/kkpmx_core.py)

### Inferences（可直接落地的插件规则）
- 贴图落盘：统一转为 32bit PNG（透明）或 24bit PNG/BMP（不透明），文件名只用 ASCII，置于模型目录下 `tex/` 等一级子目录，相对路径用 "/"；禁止 `toon01.bmp～toon10.bmp` 作为自定 toon 文件名；写 PMX 前用 cp932 试编码所有名称与路径（mmd_tools 与 Nuthouse01 都这样做）。
- 默认材质参数（综合 mmd_tools 默认 + eishin178 + LearnMMD game-rips）：Diffuse 1.0（有贴图时）/ Ambient 0.4～0.5 灰 / Specular 低（0.1 左右）/ Reflect 20～50 / Alpha 1 / 边线 1.0 黑 / 地面影+自阴影贴图+自阴影 开 / 両面 关；toon：皮肤 toon02、其他 toon01；sphere 默认关（头发可选加算）。
- XPS 渲染组映射：`rgAlpha=True` 的组 → 标记为透明材质：排到同一父对象材质列表尾部、默认关闭边线、按需开両面（薄片）；RG 10/13/14/15/21（无光照）→ 候选"自发光/UI"材质，可把 Ambient 设为 1 以减弱阴影；非 diffuse 槽（lightmap/bump/mask/specular/environment/emission）不进 PMX 槽位，仅记录到材质 comment（例如 `[:XPS:] RG=22; bump=xxx.png; spec=yyy.png`），供 MME/Ray-MMD 用户手工接入；是否把 lightmap 预乘进 diffuse 需用户选项。
- 材质排序：不透明主体 → 脸 → アイライン/眉 → 瞳 → 高光 → 透明/半透明材质（头发透明边、睫毛、玻璃等）；若半透明材质相互重叠，按"内层/背面先、外层/正面后"。
- 可选部件（XPS "+"/"-"）：默认显示的"−"部件生成 乗算×0 隐藏モーフ；默认隐藏的"+"部件导出为 alpha=0、edge alpha=0 的材质，并生成 加算 +1（含 edge alpha 回加）显示モーフ；命名可采用 `<部件名>` / `<部件名> 透明化`（khsk）或 `Show:<x>`/`Hide:<x>`（KKPMX），全部放「その他」面板并加入「表情」表示枠。

## 问题 2：表情（モーフ）—— 标准表情表与无 shape key 游戏模型的生成策略

### Takeaway
PMX モーフ分 眉(1)/目(2)/口(3)/その他(4) 四个面板（0 为隐藏，不得放进表示枠否则 MMD 崩溃）；VMD 口型/眨眼动作依赖日文名精确匹配（15 字节 Shift-JIS 上限），核心集合为 あ/い/う/え/お/ん + まばたき/笑い/ウィンク/ウィンク右/ウィンク２/ｳｨﾝｸ２右 + 真面目/困る/にこり/怒り/上/下 + 照れ/涙 等（Tda/あにまさ 系）。对没有 shape key 的游戏模型，vroid2pmx 与 KKPMX 的做法是：用 群モーフ 把"顶点モーフ + ボーンモーフ（下颌/眼皮骨）+ 眉"打包成标准名，用 材質モーフ 做 星目/はぁと/照れ/涙/エッジOFF，用 UV/材质切换做高光关闭；VRM 预设（A/I/U/E/O/Blink/Joy…）与 VRChat 视位（vrc.v_aa 等）与 MMD 名之间都有既定映射。

### Cited Findings

#### 2a. 面板与命名硬约束
- 【硬性】モーフ面板值 "1 = Eyebrows, 2 = Eyes, 3 = Mouth, 4 = Other"；类型 Group(0)/Vertex(1)/Bone(2)/UV(3)/Material(8) 等 — [PMX 2.0 规范](https://gist.github.com/felixjones/f8a06bd48f9da9a4539f)

## 问题 3：物理（剛体 / ジョイント 的自动生成与参数惯例）

### Takeaway
自动生成工具链里，Blender 侧 mmd_tools 只提供"按选中骨骼生成剛体/ジョイント"的基础算子（`mmd_tools.rigid_body_add` 默认尺寸 0.6×骨长、质量 1、摩擦 0.5、线性/角阻尼 0.04/0.1、碰撞组 1；`mmd_tools.joint_add` 默认角度限制 ±45°），MMD Tools Append 并不做链式剛体生成而是把剛体转为布料；真正的参数经验来自 PMXE 生态（PmxTailor 的材质预设与公式、曲面自動設定プラグイン、KKPMX 的硬编码）。共识是：链首剛体 ボーン追従(static)、链身 物理演算、身体碰撞体为 ボーン追従 且高阻尼；头发质量由根到梢递减、阻尼高（0.9～0.999）、无反弹/低摩擦、关节限角小（±10°级）并靠弹簧回弹；裙子用薄板状箱剛体加纵/横/斜 ジョイント；崩坏主因是剛体初始重叠、孤儿ジョイント（rb 索引 -1 直接导致 MMD 崩溃）与碰撞组设置错误。

### Cited Findings

#### 3a. 格式层面
- 【硬性】剛体形状 Sphere(0)/Box(1)/Capsule(2)；物理模式 "0 = Follow bone, 1 = Physics, 2 = Physics + bone"；字段 group id(byte)、non-collision group(short 位掩码)、mass、move attenuation、rotation damping、repulsion、friction；ジョイント类型 Spring 6DOF(0)/6DOF(1)/P2P(2)/ConeTwist(3)/Slider(4)/Hinge(5)，含位置/旋转上下限与弹簧 — [PMX 2.0 规范](https://gist.github.com/felixjones/f8a06bd48f9da9a4539f)
- 【硬性】ジョイント引用的剛体索引为 -1 会使 MMD 崩溃（`find_crashing_joints`）；ボーン追従剛体无关联骨骼"usually doesn't cause crashes but is definitely a mistake" — [model_overall_cleanup.py](https://github.com/Nuthouse01/PMX-VMD-Scripting-Tools/blob/master/mmd_scripting/scripts_for_gui/model_overall_cleanup.py)
- "The most common cause of MMD crashes after editing physics is orphaned joints" — [LearnMMD: Easiest Way To Add Hair Physics](https://learnmmd.com/http:/learnmmd.com/add-hair-physics-in-pmx-editor/)（评论区）
- 物理后变形：mmd_tools 骨骼属性 `transform_after_dynamics`（"After physics"） — [mmd_tools/properties/pose_bone.py](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/mmd_tools/properties/pose_bone.py)；Nuthouse01 `bonedeform_fix` 把 `deform_after_phys` 的骨骼视作更高变形层，并修正"子骨必须在父骨/付与親/IK 目标之后变形"的关系 — [bonedeform_fix.py](https://github.com/Nuthouse01/PMX-VMD-Scripting-Tools/blob/master/mmd_scripting/overall_cleanup/bonedeform_fix.py)
- 剛体类型用法实例："ネクタイ" 用 物理+ボーン位置合わせ 以避免超出关节限制 — [scrapbox motoso/PMX](https://scrapbox.io/motoso/PMX)

- 派生公式：移動/回転減衰 = clamp(1 − (1 − 空気抵抗/5)·(質量/10)·1.2, 0, 0.9999)；髪 再 ×1.2，胸 ×3；摩擦 = 空気抵抗/5 × 0.7；ジョイント基准限角 = 89°·(1 − 空気抵抗/5)，Y 轴 180°·(1 − 空気抵抗/5)；縦ジョイント比例 0.9（胸 0.2）、横 0.8（胸 0.1）、斜 1（胸 0.05），最小 2°；回転バネ = 形状維持比 × 系数 × 質量，系数 縦 40/30、横 30/20、斜 20/10（胸 一律 60）；髪：限角 ÷1.2、バネ ÷2.5；移動制限：縦 0；横 Y −(1−空気抵抗比)·0.5 ～ +其半；斜 −(1−比)·0.7 ～ +其半（胸为 0）；ジョイント位置=ボーン位置时系数 ×1.3（逆向 ×0.7） — [ParamPanel.py](https://github.com/miu200521358/pmx_tailor/blob/main/src/form/panel/ParamPanel.py)

## 问题 4：表示枠（显示枠）标准结构

### Takeaway
PMX 必须有且仅有两个特殊枠 "Root"（只放 全ての親/第一根骨）与 "表情"（放全部モーフ，且所有モーフ只能集中在此一枠）；其余按 センター / ＩＫ / 体(上) / 髪 / 腕 / 指 / 体(下) / 足 / 服装・物理 / その他 约 10 个枠组织，每根可见骨与每个非隐藏モーフ都要注册一次且不可重复，表示枠中モーフ总数要 <250。

### Cited Findings
- 【硬性】表示枠 "0 = normal frame, 1 = special frame"；元素类型 Bone(0)/Morph(1) — [PMX 2.0 规范](https://gist.github.com/felixjones/f8a06bd48f9da9a4539f)
- 【硬性】PMXE 状態検証 "Display panel" 10 项：枠无名/重名、骨骼未注册、モーフ未注册、骨骼重复注册、モーフ重复注册、引用不存在的骨/モーフ、零个枠、"Root and/or Expressions (System) Display Panel Groups… do not exist" — [PMX error checker quick reference](https://github.com/powroupi/blender_mmd_tools/wiki/PMX-error-checker-quick-reference)
- mmd_tools 新模型默认创建 `Root`(name_e "Root") 与 `表情`(name_e "Facial") 两个 `is_special` 枠，Root 内放骨架第一根骨；`initialDisplayFrames(reset=False)` 保证 Root 在 0、表情 在 1 — [core/model.py](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/mmd_tools/core/model.py)、[core/pmx/__init__.py](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/mmd_tools/core/pmx/__init__.py)
- `mmd_tools.display_item_quick_setup` 四种模式：RESET（清空重建默认）、FACIAL（"Load all morphs to faical frame"，把 vertex/bone/material/uv/group 全部モーフ载入「表情」并保持原顺序）、GROUP_LOAD（从 Bone Collections 同步出枠）、GROUP_APPLY（反向同步） — [operators/display_item.py](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/mmd_tools/operators/display_item.py)
- Nuthouse01 `dispframe_fix` 规则：Root 枠（name_jp=="Root" 且 is_special）内容强制为仅 "全ての親"（找不到则用骨 0）；若无 "センター" 枠则在索引 2 新建，并确保包含 操作中心/センター/グルーブ/腰；删除面板 0（隐藏）モーフ、重复条目、空的非特殊枠；把未注册的可见启用骨骼与非隐藏モーフ补入（モーフ补到 "表情"，"should ALWAYS be at index 1"）；MAX_MORPHS_IN_DISPLAY = 250；"UTTERLY IMPOSSIBLE to get multiple frames containing morphs, they are always collapsed into one" — [dispframe_fix.py](https://github.com/Nuthouse01/PMX-VMD-Scripting-Tools/blob/master/mmd_scripting/overall_cleanup/dispframe_fix.py)
- 社区标准枠结构（Ziv27）：[Root] 仅 全ての親（"This bone AND ONLY THIS BONE should be able to move your entire model around"）；[表情] 全部モーフ；センター（センター、グルーブ）；ＩＫ（足 IK）；体(上)（上半身/上半身2/上半身3）；髪（髪、もみあげ、アホ毛…）；腕（肩臂，不含指）；指（含"指"的骨）；体(下)（下半身）；足（非 IK 腿骨）；マント/スカート/ジャケット（物理衣物）；服；頭（目/舌/首/頭）；その他；建议约 10 类，常见问题是"sheer bloat"与重复骨 — [DeviantArt: MMD: Cleaning up the Display panel](https://www.deviantart.com/ziv27/journal/MMD-Cleaning-up-the-Display-panel-963649322)
- LearnMMD 的精简建议：保留 Root, Expression, Center, IK, upper/lower body, arms, fingers, legs — [LearnMMD: PMXInfo](https://learnmmd.com/http:/learnmmd.com/pmxeditor-pmxinfo-analyzing-optimizing-mmd-models/)
- KKPMX："Remove items with idx == -1 from dispframes [<< crashes MMD]"；为 Chest/Skirt 骨各加一枠以便在 MMD 中关闭其物理 — [kkpmx_core.py](https://github.com/CazzoPMX/KKPMX/blob/master/src/kkpmx_core.py)
- 新建モーフ后必须手动加入「表情」枠（"表示枠タブで…「表情」を選択し…[+追加]"） — 搜索摘要（材質ON/OFFモーフ生成 使用说明）；[rio-vroidmmd](https://rio-vroidmmd.hatenablog.com/entry/2021/11/15/105821) 亦要求 "Add morphs to display frames after creation"

### Inferences
- 插件导出前应：按 Nuthouse01 规则生成 Root(全ての親)/表情(全モーフ)/センター(操作中心,センター,グルーブ,腰)，再按骨名前缀分配 ＩＫ/体(上)/腕/指/体(下)/足/髪/スカート/その他；对 XPS 的大量未知骨骼统一放 "その他"（或按父链归到 髪/服）；物理链骨单独成枠便于用户关闭物理。
- 隐藏モーフ（面板 0，如 "あ頂点"、"星目材質"）绝不能进表示枠；表示枠モーフ数超过 250 需裁剪或合并群モーフ。

- 表示枠标准名的官方来源（あにまさ式ミク 自带结构 / VPVP wiki）未能直接核对，只有社区文章与工具代码。

#### 5c. mmd_tools（v4.5.14）Model Validation
- 算子与检查内容 — [operators/model_validation.py](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/mmd_tools/operators/model_validation.py)：
  - `mmd_tools.validate_model`（"Validate Model Name"）：模型 JP/EN 名能否 cp932 编码、是否含用户配置的 "additional unallowed characters"。
  - `mmd_tools.validate_bones`（"Validate Bone Limits"）："Duplicate bone name"、"exceeds 15 bytes in cp932"、不可编码字符、额外禁用字符。
  - `mmd_tools.validate_morphs`：重名、"name too long (exceeds 15 bytes in cp932)"、不可编码。
  - `mmd_tools.validate_textures`：缺失文件（按材质列出）、"Different textures with same path"、"Texture filename conflict"、文件名主干禁用字符。
  - `mmd_tools.fix_model_issues` / `fix_bone_issues` / `fix_morph_issues`：自动替换不可编码字符、在 15 字节内生成唯一名（截断 + 后缀）。
  - `mmd_tools.fix_texture_issues`：toon 缺失→共享 toonNN（否则 toon01）、统一同路径贴图名、冲突文件改名复制、删除无文件 image block。
- 相关清理算子：`mmd_tools.clean_shape_keys`、`mmd_tools.clean_rig`、`mmd_tools.clean_additional_transform`、`mmd_tools.clean_duplicated_material_morphs`、`mmd_tools.translate_mmd_model`、`mmd_tools.material_cleanup_texture` — [mmd_tools/operators](https://github.com/MMD-Blender/blender_mmd_tools/tree/main/mmd_tools/operators)
- 导出侧防御：剛体位置/旋转/缩放出现 NaN 时回退默认并告警；表示枠中找不到的骨/モーフ记录 warning 并跳过 — [core/pmx/exporter.py](https://github.com/MMD-Blender/blender_mmd_tools/blob/main/mmd_tools/core/pmx/exporter.py)

### Inferences
- 插件的"导出前自检"可直接按 PMXE 10 类 49 项实现为规则清单，并复用 Nuthouse01 的可编程修复顺序：uniquify → prune vertices/faces → prune bones → weight cleanup → dispframe → bonedeform → alphamorph → winnow → translate；再跑 cp932/15 字节/贴图路径检查（与 mmd_tools 4.5 的 validate_* 等价）。
- 由于 Nuthouse01 工具 2022 年起停更，建议把其规则移植为插件内部实现，而不是依赖外部 exe；mmd_tools 4.5 的 `validate_*/fix_*` 可在 Blender 内直接调用作为第二道门。
