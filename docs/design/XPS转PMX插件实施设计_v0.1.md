# XPS → PMX 转换插件实施设计（v0.1 草案）

> 状态：草案，等 owner 审阅后再进入实现。除 `xps_to_pmx/core/xps/`（XPS 读取器，18 项测试通过）外，尚未写插件代码。
> 依据：`docs/research_notes/XPS 转 PMX 方案调研/` 01–11 号笔记（下文用 [01]…[11] 引用），以及 2026-10-24 的 14 项决策。
> 读法：§1–§3 是边界、约束与架构，最需要确认；§4–§11 是各阶段规格；§12–§13 是测试与里程碑；§14 是需要拍板的事项。

## 1. 目标与边界

**v1 目标**
- 在 Blender 3.6.15 中把 `.xps` / `.mesh` / `.mesh.ascii` 转成能直接在 MMD 跳标准动作的 PMX 2.0。
- 骨骼自动识别并映射到 MMD 标准骨与准标准骨；缺失骨按规则补全；每根源骨的去向都可查、可改；映射数据用 CSV 维护。
- T 姿势转 A 姿势；缩放按实测规则。
- 表情可选骨骼 morph 或顶点 morph，另有 AUTO 逐个自动选。
- 物理按身体、胸（含臀）、衣物、头发四类分别生成。
- 导出前后做 MMD 兼容校验，崩溃级错误阻断导出。
- PMX 导入 Blender 后，按导入 XPS 时记录的材质清单回挂高清材质。

**v1 不做**
- Blender 4.x/5.x、mmd_tools 2.x/4.x。mmd_tools 调用集中在一个桥接模块，以后升级只改这一处（[08] Q14 已列出 1.0.2 与 4.5.5 的接口对照）。
- PMX 2.1 特性（SDEF、QDEF、软体）。
- 无骨网格自动绑骨、顶点表情雕刻工具、VMD 重定向。

## 2. 环境与硬约束

| 项 | 取值 |
|---|---|
| Blender | 3.6.15，`D:\Program Files\blender-3.6.15-windows-x64\blender.exe`；Python 3.10.13；自带 numpy |
| PMX 写出 | 已安装的 mmd_tools 1.0.2（legacy 插件，`import mmd_tools`，`bl_info["version"] == (1, 0, 2)`） |
| XPS 读取 | 自写读取器（已完成）。不依赖 XNALaraMesh：本机 3.6 副本按 latin-1 读字符串，会把 UTF-8 名字读乱 [09]，上游也没有许可证 [01]；它只在测试里做对照 |
| 许可 | GPL-3.0-or-later（要吸收 Convert_to_MMD5 的 GPL 代码，并调用 mmd_tools） |
| 安装方式 | 仓库目录 `xps_to_pmx/` 目录联接到 3.6 的 addons；核心模块支持 `importlib.reload`；用户数据（CSV 覆盖表、映射、报告）放插件目录外 |
| 界面语言 | 中文文案，MMD 骨名、表情名保持日文原样 |

**12 条硬约束**（来自上次 C2M 尝试的复盘 [10] §1b.6；代码评审和测试都按这张表检查）

1. 一个插件、一条管线；“一键”和分步按钮调用同一组阶段函数。
2. 骨骼规格与映射只有一份 CSV；代码里不写骨名字面量；载入时校验全角/半角、空格、`IK`/`ＩＫ`。
3. 状态存 Blender 数据（PropertyGroup / CollectionProperty），随 .blend 保存和 Undo；不用模块级全局变量。
4. 每个阶段返回结构化结果（ok / warn / error）；失败必须可见，禁止静默回退；报告写 JSON。
5. CSV / JSON 带 schema 版本；未知列、缺列直接报错；只有一处解析代码。
6. 检查器的期望只来自规格表，不来自被检查对象；每条检查配一个反例测试。
7. 自动识别 = 名称表 + 拓扑 + 几何；输出置信度，允许“拒绝映射”；一对一。
8. 文档只写已实现并验证过的行为，附验证数据。
9. 纯 Python 核心配 pytest 离线测试；Blender 端用无头端到端测试。
10. 目录联接 + reload 的开发循环，不用复制脚本。
11. 先在 1–2 个真实模型上把一个阶段做到可验收，再做下一个；优先移植已验证的算法。
12. 分层 core（无 bpy）/ blender（bpy 适配）/ ui；阶段内部按“分析（只读）→ 计划（可审阅）→ 执行 → 自检（只读）”。

## 3. 架构

### 3.1 目录与分层

```
xps_to_pmx/                      插件包（联接到 addons）
  __init__.py                    bl_info、注册（reload 友好）
  data/                          随插件发布的默认规格表（只读）
    bone_slots.csv               骨骼规格 + 各骨架约定的别名（唯一真理源）
    morphs.csv                   表情名单、面板、顺序、配方 id
    physics_presets.csv          四类物理的预设参数
    texture_roles.csv            贴图后缀 → 材质角色（高清回挂用）
  core/                          纯 Python，不 import bpy / mathutils；可用 numpy
    xps/                         XPS 读取器（已完成）
    spec/                        CSV 载入与校验 → 只读的规格对象
    rig/                         RigData 快照类型、识别、辅助骨分类、补骨公式
    weights/                     权重补丁算法（合并、切分、髋部渐变、扭转分配）
    checks/                      检查规则与报告模型
    plan.py                      转换计划数据类 + JSON（带 schema 版本）
  blender/                       bpy 适配层
    importer.py                  XpsModel → Blender 对象，并记录材质清单
    snapshot.py                  Blender → RigData（骨、权重矩阵）
    apply.py                     应用 BonePatch / WeightPatch
    pose.py                      T→A 烘焙（保住形态键）
    mmdtools_bridge.py           唯一 import mmd_tools 的模块（1.0.2 适配）
    materials.py / morphs.py / physics/ / hd_materials.py
  pipeline/                      阶段函数，可无头调用，返回 StageResult
  ops/                           操作符：只做参数收集并调用 pipeline
  ui/                            面板与 UIList：只读属性、只调用操作符
  props.py                       PropertyGroup 定义
tests/                           pytest 离线测试（core）
tests_blender/                   无头端到端测试（blender -b --factory-startup --python …）
scripts/                         样本测量、批处理入口
docs/                            调研、设计、测试协议、验收记录
```

依赖规则用一个测试扫描 import 来强制：`core/*` 不得 import bpy、mathutils 或 `blender/*`；只有 `blender/mmdtools_bridge.py` 可以 import mmd_tools；`ops/*` 只调用 `pipeline/*`；`ui/*` 不调用 `blender/*`。

### 3.2 数据流：快照 → 补丁 → 应用

- **读**：`blender/snapshot` 把骨架和权重抽成纯数据 `RigData`（骨名、父、head/tail、roll、是否变形、原始 XPS 名；网格顶点坐标与稀疏权重矩阵）。
- **算**：`core` 的函数输入 `RigData`、规格表和计划，输出补丁：`BonePatch`（建骨、改名、改父、删骨、写 mmd 属性）和 `WeightPatch`（逐顶点、逐组的增减，带作用范围掩码）。
- **写**：`blender/apply` 应用补丁；每个补丁附带“预期结果”，应用后立即自检。

这样识别、分类、补骨公式、权重切分都能用自写读取器在真实 XPS 数据上离线测试，不必启动 Blender（Blender 坐标 = XPS 的 (x, −z, y) [01]）。权重补丁带范围掩码，直接落实 C2M 设计过但没实施的 Zone/WeightPatch 方案 [10] §1b.3：髋部过渡区的补丁不会被别处的清理步骤改写。

### 3.3 状态模型

- 场景级 `scene.xps2pmx.jobs`，每个 XPS 一个 job：源文件、选项（缩放、A 姿势角、补骨档位、表情模式、物理开关…）、映射槽（slot_id → 源骨、状态、置信度、来源 csv/auto/user）、其余骨的处置（动作、目标、理由）、各阶段状态与报告。
- 导入时给每根骨写 `bone["xps2pmx_src"] = 原始 XPS 骨名`，改名之后映射仍能找到骨。
- 骨架对象写 `obj["xps2pmx_job"] = job id`；面板显示活动骨架所属的 job。
- “重来” = 删除本 job 生成的对象，重新导入 XPS，保留计划（映射、处置、选项），再按计划重跑。XPS 导入只要几秒，比快照可靠。
- 映射与计划可以导出为 CSV / JSON（复用、分享、回归测试），但 .blend 里的 job 是唯一真理源。

### 3.4 mmd_tools 1.0.2 桥接层

全部 mmd_tools 调用集中在 `blender/mmdtools_bridge.py`，按 [08] Q14 的分阶段清单实现。几条直接影响实现的 1.0.2 事实：

| 事实（[08]） | 设计对策 |
|---|---|
| `Model.create(name, name_e, scale, obj_name, armature=…, add_root_bone=False)`；关键字是 `armature`（4.5.5 是 `armature_object`）；不建骨骼组，不建表示枠 | 桥接层统一封装；表示枠自己建 |
| 骨序 = 第一个带 `mmd_bone_order_override` 修改器的网格的顶点组顺序，`bone_id` 不参与 | 建零顶点辅助网格 `000_mmd_bone_order` 承载骨序；同时写 `bone_id` 以兼容新版，且必须在付与之前写 |
| 付与只读 `mmd_bone` 属性；源骨不存在时 setter 静默写入 −1，导出时写出索引 −1 | 写完立即读回校验；“付与目标为空”列为阻断级检查 |
| dummy / shadow 骨在骨层 9 / 8（不是骨骼组），只在两骨 X/Y 轴点积 ≤0.99 时生成 | 不手工建中转骨，统一调用 `apply_additional_transformation`；检查器验证结构 |
| IK 约束在目标骨的父骨上；`iterations` 即 loop；单位角在 `ik_rotation_constraint`（默认 1 rad）；膝限制用 `mmd_ik_limit_override`（`owner_space='POSE'`） | IK 参数全部显式写入，不依赖默认值 |
| 用常规属性写任何 `mmd_material` 字段，会把材质输出改接到 `mmd_shader`；用 ID 属性写不会 | 材质参数一律用 ID 属性写，保住高清节点 |
| 导出操作符默认 scale 为 1.0；直接调用导出函数不会切到 REST 姿态 | 桥接层显式传 `scale=12.5`，负责 REST 切换与恢复 |
| morph 导出顺序按类型固定（顶点→骨骼→材质→UV→组）；未登记的形态键排最前 | 顶点 morph 必须登记；顺序按 morphs.csv |
| 不导出打包贴图 | 导入时贴图保持外部文件 |
| `createRigidBody` 会新建并启用 rigidbody world、改变选择 | 建完关闭 world、恢复选择（沿用 mmd_cloth_physics 的 `with_world_off`） |

### 3.5 面板

沿用 Convert-to-MMD 的逐槽布局，加上你现有插件的习惯：带圈数字的阶段按钮、一键、重来、报告框末行写“下一步” [10] §10.4。

- 页签 “XPS→PMX”：转换的所有阶段。
- 页签 “MMD”（与你的游戏材质、Cloth Physics 等并列）：PMX 导入后才用的面板，即高清材质回挂。

主页布局：

```
┌ XPS→PMX ──────────────────────────────────────────────┐
│ XPS 文件 [.............................] [① 导入]       │
│ [② 自动识别] [检查映射]   约定: [xna_lara ▼]            │
│ [导入映射CSV] [导出映射CSV] [清空]                       │
│ ┌ 躯干 ───────────────────────────────────────────────┐ │
│ │ 全ての親 ✓ [◎][root ground              ]           │ │
│ │ センター ○ [◎][                         ] 将生成    │ │
│ │ 下半身   ⚠ [◎][pelvis                   ] 见诊断    │ │
│ │ 上半身   ✓ [◎][spine lower              ]           │ │
│ │ …                                                   │ │
│ ├ 上半身（左 | 右）───────────────────────────────────┤ │
│ │ 腕*  ✓[◎][arm left shoulder 2] | ✓[◎][arm right …] │ │
│ ├ 下半身（左 | 右）  ├ 手指（每行三节）               │ │
│ └─────────────────────────────────────────────────────┘ │
│ 其余骨骼 [全部 ▼]   UIList：源骨 / 处置 / 目标 / 理由    │
│ [③ 预处理] [④ 生成MMD骨架] [⑤ 表情] [⑥ 物理]            │
│ [⑦ 检查] [⑧ 导出PMX]        [一键 ①→⑧] [重来]           │
│ 报告：…                       下一步：…                 │
└────────────────────────────────────────────────────────┘
```

- 每个槽位一行：日文名、状态图标、吸管按钮（取选中骨）、`prop_search` 选骨框。状态：✓ 已映射且检查通过；⚠ 有警告；✗ 错误（必需骨缺失、侧别错、层级错）；○ 留空、将由补骨生成；✎ 用户手改过。
- 改一个槽位只触发与它相关的检查，不重新识别。自动识别默认不覆盖用户手改过的槽（Convert_to_MMD5 的一键流程会覆盖，这是要改掉的问题 [10a] §2.17）。
- “其余骨骼”列表显示每根未映射源骨的处置（并入某骨 / 保留为物理链 / 道具 / 删除）和理由，可以逐行改。
- 检查页（⑦）列出所有检查结果，每条带“定位”按钮（选中骨、高亮顶点）。

## 4. 阶段规格

| 阶段 | 做什么 | 主要输出 | 阶段末自检 |
|---|---|---|---|
| ① 导入 | 读 XPS；建骨架、网格、UV、自定义法线、顶点色；权重归一化并限 4；建预览材质；记录材质清单 | Blender 对象；job；材质清单 | 顶点、面、骨数与文件一致；权重和为 1；每顶点 ≤4 个影响 |
| ② 识别 | 判断骨架约定；按 CSV 别名、拓扑、几何填映射槽；给其余骨分类；下半身诊断 | 映射槽、处置表、诊断 | 映射检查（§5.4） |
| ③ 预处理 | 按处置表合并扭转骨与辅助骨的权重、删无权重骨；缩放与贴地；T→A 烘焙；骨位规范化 | 预处理后的骨架与网格 | 臂角 = 目标 ±0.5°；形态键数不变；网格无撕裂 |
| ④ 生成 MMD 骨架 | 改名；三档补骨；下半身构造；权重规则；IK；付与；局部轴；骨序；收编为 mmd_tools 模型；材质 MMD 参数；表示枠 | mmd_tools 模型 | 规格检查（结构、骨序、付与、影子骨、IK） |
| ⑤ 表情 | 按模式生成标准表情与可选件的材质 morph | morph | 名字、面板、顺序；噪声偏移 |
| ⑥ 物理 | 身体、胸/臀、衣物、头发分别生成 | 刚体、Joint | 都绑了骨；初始不重叠；Joint 两端存在 |
| ⑦ 检查 | 汇总全部检查 | 报告 | — |
| ⑧ 导出 | REST 姿态导出 PMX（×12.5）并复制贴图；写材质清单与报告；用 `pmx.load` 读回复检 | PMX、`<名>.materials.json`、`<名>.report.json` | 读回检查（§12.1） |
| 回挂（MMD 页签） | 对导入 Blender 的 PMX 按材质清单建高清节点，可在 MMD / HD 之间切换 | 高清材质 | 匹配率报告 |

### 4.1 ① 导入的细节

- 读取器（已完成）支持 `.xps`（2.x / 3.x）、无头 `.mesh`、`.mesh.ascii`、`.pose`。XPS 11 会在文件尾写入保存者电脑的局域网 IP 和 MAC [09]；读取器只记录尾部字节数，不读内容，也不写进任何输出。
- 权重：本机样本里有 5 个模型约 2.88 万个顶点的权重和超过 1.01；7 个模型有超过 4 个影响的顶点，最多 33 个 [09]。导入时统一归一化并保留前 4 个。
- `unused*` 骨不能按名字删除：82 个模型里有 1928 根 `unused*` 骨带权重，包括扭转骨和原始 pelvis [09]。导入时只隐藏，处置交给 ② 的分类。
- 材质清单是高清回挂的数据源。每个网格记录：原网格名；渲染组号与参数；按渲染组槽位顺序得到的各角色贴图绝对路径（diffuse / lightmap / bump / mask / microbump1/2 / specular / environment / emission）；alpha 方式；UV 层；法线绿通道标志。本机样本只出现渲染组 1–9、22–31、38–41 [09]。

## 5. 骨骼映射与检查

### 5.1 `bone_slots.csv`：规格与别名放在一张表里

每行一个槽位（既有源骨映射槽，也有生成骨），列分四组：

| 列组 | 列 | 说明 |
|---|---|---|
| 身份 | `slot_id` | 稳定的 ASCII id，沿用 Convert_to_MMD5 的 key（如 `left_upper_arm_bone`）；新增的生成骨用同样风格（如 `left_arm_twist_bone`） |
| | `name_j` / `name_e` | 规范 MMD 名（全角数字、`ＩＫ` 全角、`上半身2` 半角）；`name_e` 取 mmd_tools 内置译名 |
| 界面 | `group` / `order` / `row_type` | 面板分组、顺序、行型（single / symmetric / finger） |
| | `side` / `mirror` | C / L / R；对侧槽 |
| 规格 | `tier` | 0 = 必须来自源骨；1 / 2 / 3 = 缺失时由第几档补骨生成 |
| | `required` | 缺失即阻断 |
| | `parent` | 期望的父槽（检查器与补骨共用） |
| | `deform` / `visible` / `controllable` / `movable` | PMX 标志的期望值 |
| | `grant_parent` / `grant_rate` / `grant_type` | 付与源、比例、旋转或移动 |
| | `transform_order` | 変形階層 |
| | `ik_*` | IK 骨的目标、链与角度限制、loop、单位角 |
| | `display_frame` | 所属表示枠 |
| | `recipe` / `recipe_args` | 缺失时的生成配方 id 与参数（如 `twist`、`t=0.6`） |
| 别名 | 每种骨架约定一列：`xna_lara`、`daz_g8`、`bip001`、`valvebiped`、`mixamo`、`auto_rig_pro`、`re_engine`… | 单元格可写多个候选，用 `\|` 分隔；`+名字` 表示把该骨权重并入本槽（如 DAZ 的 `lShldrBend\|+lShldrTwist`） |

- 第一行写 `# xps_to_pmx bone_slots schema=1`。未知列、缺列、重复 `slot_id`、`name_j` 不合规（全角/半角、空格、IK 写法）、左右槽不成对，都在载入时报错。规则来自 [10a] §5.2 A。
- 名字比较前做 NFKC、小写、分隔符归一化；报告里显示原始差异。
- 用户覆盖：插件目录外放一份同 schema 的 CSV，按 `slot_id` 覆盖默认表。

**种子数据**：bones_renamer 的 22 种骨架 × 56 槽、Convert_to_MMD5 的 25 个预设、你 2024 年的骨名清单、`Purifier_bones.txt` / `inase_bones.txt`、pmxconv 的 `lang.ini`，合并去重 [10] §10.1。数据源之间的矛盾（例如 `spine lower`）不在表里静默取舍，交给识别阶段按几何规则判定（§5.3）。

### 5.3 自动识别

分三级，结果都带置信度和理由，一根源骨只能占一个槽：

1. **名称表**：按骨架约定列做精确匹配（归一化后）。骨架约定按命中数自动判断，同时报告第一名与第二名的差距，差距太小时提示人工确认（bones_renamer 的子串误判就是反例 [10a] §4.3）。
2. **拓扑 + 几何**：移植 Convert_to_MMD5 的 `skeleton_identifier`（脊柱链、腿/臂分叉、手指链、眼睛对称配对）[10a] §2.8，填名称表没填上的槽，并检查名称表的结果是否与几何矛盾。
3. **辅助骨分类**：移植 `helper_classifier`（扭转候选、髋部 pelvis 类、保留类、头发/衣物/胸链）[10a] §2.8，生成“其余骨骼”的默认处置。

两条专门的规则：

- **脊柱不插骨，按节数和位置映射**。源脊柱 1 节 → 上半身（上半身2 由补骨生成）；2 节 → 上半身、上半身2；3 节以上 → 头部离标准 上半身2 位置（上半身→首 的 0.35 处）最近的一节作 上半身2，它下面的作 上半身 / 上半身1，上面的作 上半身3。这对应 18 系列的“节数随源” [11] §13.3，也绕开了 Convert_to_MMD5（新插 上半身1）和 xps_to_mmd（新插 上半身3）两种互相矛盾的插骨策略。
- **`spine lower` 不靠查表决定**：它对应 上半身 还是 下半身，由下半身诊断（§6）按权重分布判定。

### 5.4 映射检查器

检查的期望值只来自 `bone_slots.csv`。分三级：**阻断**（不修就不能进入下一阶段）、**警告**、**提示**。

## 6. 下半身专项

实测证实了“下半身容易缺”的原因：本机通用名模型缺的通常正是 `pelvis`，因为 lezisell 系把原 `bip001 pelvis` 改成了 `unused bip001 pelvis`，权重还留在它身上 [09] §3.2。

**诊断**（② 阶段，只读）：列出所有候选骨——位于两腿分叉骨与腰节之间、靠中线（|x| < 身高的 1%）、带权重；报告每根的权重顶点数和权重 50% 高度，并归入四种情形。下表中 L = 上半身 头与 足 头的高度差。

| 情形 | 特征 | 处理 |
|---|---|---|
| A 干净的髋骨 | 有从腰节起向下的 pelvis/hips 骨，其 w>0.5 部分的 Y 中位数在 [足 − 1.0L, 上半身 + 0.3L] 内 | 原样改名或合并为 下半身。18 系列就是这样做的：下半身权重逐顶点等于源 pelvis + hip 权重 [11] §5.2 |
| B 权重在 `unused` 或辅助骨上 | 如 lezisell 的 `unused bip001 pelvis` | 并入 下半身，与 A 相同 |
| C 髋骨兼管下腹 | root/hips 骨的 w>0.5 中位数高于腰节 | 按高度切分：`t = (y − 足Y) / L`，`w下半身 = w·S(t)`，`w上半身 += w·(1 − S(t))`；S 为 smoothstep，S(0.5)=1、S(1.75)=0 [11] §5.4 |
| D 完全没有髋骨 | 腿直接挂在脊柱上，髋部权重在最低脊柱节 | 同 C，切分对象换成最低脊柱节；腿侧保留源权重 |

**骨位**：头 = 上半身 头（腰节），Z = 两侧 足 头 Z 的平均；尾竖直向下，长 1.0×H/20.8（H 为导出后总高）；父 = 腰（没有 腰 时 = グルーブ），与 上半身 同父，禁止 上半身 挂在 下半身 下；子 = 腰キャンセル左/右 → 足/足D，臀、生殖、裙根直接挂 下半身 [11] §5.4。

**髋部过渡区**：移植 C2M 旧插件按 Purifier Inase 实测校准的算法——在大腿顶端 46% 区间建 下半身↔足D 渐变；只在 D 系权重 ≥0.6 的顶点上清 下半身；按 X（±0.02）严格分侧；过渡区内禁止全局归一化 [10] §1b.2。

**验收检查**（做成检查项）：下半身 有权重；Σw / 顶点数在 0.4–0.8；w>0.5 顶点的 Y 中位数在 足 头与 上半身 头之间；t ≥ 1.75 处 下半身 权重约为 0；侧面 t=0 处 下半身 与 足 约各半；正中 t∈[−0.5, 0.5] 下半身 ≥ 0.8；上半身 与 下半身 同父；左右无交叉污染 [11] §5.4、[10] §1b.2。

## 7. 姿态与缩放

### 7.1 T 姿势 → A 姿势

| 项 | 默认 | 依据 |
|---|---|---|
| 上臂角（腕→ひじ 低于水平） | 37.5°；预设：37.5 / あにまさ 29.72+40.28 / 45 | 18 系列 37.21°–37.83°，均值 37.52° [11] §3.1；你的 ROE 流水线用 37° [10] §2 |
| 前臂 | 与上臂共线，并去掉源 T 姿势前臂的前伸（约 15.7°） | [11] §3.2 |
| 手与手指 | 随手臂整体旋转 | [11] §3.1 |
| 肩 | 骨位规范化：肩 头移到与 腕 同高同深，只改骨不改网格 | [11] §3.2 |
| 腿 | 足 / ひざ / 足首 / つま先 对齐同一 X，膝保持前移（膝弯 1.5°–4.6°）；只改骨 | [11] §3.1 |

实现：手臂按姿态旋转后烘焙为静止姿态，网格和全部形态键一起变换（矩阵法：每顶点按权重混合 `pose_bone.matrix @ bone.matrix_local.inverted()`，对 Basis 和每个形态键施加同一变换，再 `armature_apply`）[05]。优先移植你 ROE worker 里已经在 150 个模型上运行过的 `apose_arms` [10] §2。执行后实测臂角，偏离目标超过 0.5° 即报错。Convert_to_MMD5 的 36° 实现曾实际落到约 54° [10a] §2.15，这类错误必须被自检抓到。

### 7.2 缩放

实测结论 [09][11]：XPS 单位是米，123 个完整角色的高度中位数为 1.73 m。你手工完成的 PMX 用固定 ×12.5，批量版用 ×10。18 系列没有用固定倍率，而是让肩高（腕 头）落在 16.99 ± 0.04 PMX 单位，所以三对同模型的倍率分别是 10.94、11.42、12.22。

| 方式 | 说明 |
|---|---|
| 肩高归一（建议默认） | 贴地后令 腕 头高度 = 17.0 PMX 单位。Blender 里先缩放到肩高 1.36 m，再按 ×12.5 导出 |
| 固定倍率 | ×12.5（米→MMD，mmd_tools 默认）或 ×10 |
| 匹配参考模型 | 选一个 PMX，按它的肩高或头顶高对齐。同一角色在不同来源的转换里尺寸并不一致 [09] |

- 贴地：默认让脚部网格（脚踝、脚趾骨权重覆盖的顶点）的最低点落到 0，而不是全部网格的最低点，因为有的道具挂在地面以下 0.25 m [09]。
- 报告总倍率、身高、头顶高、肩高；身高超出 19–23.5 时提示 [11] §13.1。
- Blender 里的工作模型保持米制，只在导出时 ×12.5，与你现有习惯一致（导出 12.5、导入 0.08）。

### 8.1 三档补骨

| 档 | 骨 | 规则来源 |

| 1 始终生成 | 全ての親、センター、グルーブ、腰、首（缺时）、頭 的尾、両目 与 左目/右目 的付与、つま先（缺时）、足ＩＫ、つま先ＩＫ、足IK親 | 18 系列与 ssb 公式：センター Y = ひざ + 0.40·(足 − ひざ)；腰 Y = 足 + 0.40·(下半身 − 足)；両目 = 头顶 + 0.5 [11] §13.3、[03] |
| 2 默认开 | 上半身2（缺时，放在 0.35 处并切分权重）、腕捩 / 手捩 + 捩1/2/3、腰キャンセル左/右、肩P / 肩C、ダミー、親指０、操作中心 | ssb 公式；捩骨按 18 系列位置：主捩 60%，子捩 32/52/72%，付与 0.25/0.5/0.75 [11] §13.3 |
| 3 默认开（可关） | 足D / ひざD / 足首D + 足先EX（足首→つま先 的 2/3 处）；腿部权重全部移到 D 骨；変形階層 1 | [11] §4.3、§13.5 |

第 3 档在之前的报告里建议默认关闭。18 系列全部带 D 骨，且腿部权重全在 D 骨上，所以改为默认开启。

### 8.2 权重规则

| 部位 | 规则 | 依据 |
|---|---|---|
| 大腿 | ThighBend + ThighTwist → 足D（足 不带权重）；小腿 → ひざD；Foot + Metatarsals → 足首D，前端 6–10% 给 足先EX；Toe → つま先 | [11] §13.5 |
| 上臂 / 前臂 | Bend + Twist 先合并，再按沿臂位置分到 腕 / 腕捩1–3 / 腕捩 / ひじ / 手捩1–3 / 手捩 / 手首（18 系列阶梯带）；平滑版作为选项 | [11] §6.2 |
| 脊柱 / 颈 / 头 / 胸 | 源权重原样改名，不重新分配 | [11] §4.4 |
| 其余辅助骨 | 按处置表并入最近的有效变形骨（Convert_to_MMD5 `transfer` 规则，含三角肌特例） | [10a] §2.14 |
| 收尾 | 清理 <0.001；单顶点 ≤4 个影响；归一化；髋部过渡区按 §6 单独处理 | [05]、[10] §1b.3 |

### 8.3 IK、付与、局部轴、骨序、表示枠

- **IK**：默认用 あにまさ 标准值。足ＩＫ：loop 40、单位角 2 rad，链 ひざ（X −180°～−0.5°）→ 足；つま先ＩＫ：loop 3、单位角 4 rad，链 足首 [03]。18 系列实际是 loop 40/80、单位角 1 rad，也就是 mmd_tools 的默认值，说明成品没有显式设置 [11] §4.3；这组值作为预设保留（见 §14）。不生成手臂 IK。
- **付与**：单表来自 `bone_slots.csv` 的 `grant_*` 列。左目/右目 ← 両目 1.0；肩C ← 肩P −1；腕捩1/2/3 ← 腕捩、手捩1/2/3 ← 手捩，0.25/0.5/0.75；足D/ひざD/足首D ← 足/ひざ/足首 1.0；腰キャンセル ← 腰 −1。写完读回，再一次性调用 `apply_additional_transformation`。
- **局部轴**：腕 / ひじ / 手首 / 指 的 X 指向子骨，Z 取最接近前后轴的正交方向；捩骨的 `fixed_axis` = 臂方向 [05]。
- **骨序**：按规格表顺序写辅助网格的顶点组；检查父在子前、付与亲在被付与骨前、IK 链在 IK 骨前、D 系在 IK 骨之后 [08] Q14。
- **表示枠**：Root、表情、センター、ＩＫ、体(上)、腕、指、体(下)、足、髪、物理、その他，全部填满。18 系列的表示枠几乎是空的，这是要避开的缺陷 [11] §10。

### 8.4 命名

全部骨名与 morph 名必须能用 cp932 编码，且不超过 15 字节。超长的物理链骨用短名（如 `髪L1_1`），原英文名放 `name_e` [11] §13.3。胸骨默认名见 §14。

## 9. 材质与高清回挂

**导出到 PMX 的材质**（18 系列 5 个模型约 110 个材质的设定完全一致 [11] §9.1）：

- 数值：漫反射 1、高光 0.5、光泽 10、环境 0.5、共享 toon01、边线关；双面、地面影、セルフ影マップ、セルフ影全开；口腔等单面。
- 贴图：texture = XPS 漫反射。sphere 槽放 XPS 法线图、sphere 模式 0，不影响 MMD 渲染，但法线贴图路径会跟着 PMX 走。
- memo：写 `xps2pmx: key=<材质键>; RenderGroup=<n>; Params=a,b,c`，改名或拆分后仍能找回对应的清单条目。
- 名称：XPS 网格名去掉渲染组前缀和参数后缀（`4_Body_0.1_0_0` → `Body`），保留 `+`/`-`。
- 绘制顺序：不透明在前，`rgAlpha` 渲染组在后，组内保持原序 [11] §9.3。
- 全部参数用 ID 属性写入，避免 mmd_tools 改接材质输出 [08]。

**PMX 导入后回挂高清材质**（MMD 页签）：

1. 找清单：PMX 同目录的 `<名>.materials.json`。它在导出时写入，所有贴图一并复制到 `textures/`。
2. 匹配：按 memo 里的材质键 → 材质名 → 漫反射文件名的顺序。
3. 建节点：在原材质里建 `xhq_` 前缀的 Principled 网络和独立的 Output。切换 MMD / HD 只改活动输出，mmd_tools 的节点一直连着，导出不受影响。这套机制移植你三个游戏材质插件的共同部分（`set_active_output` / `set_mode` / `insert_gain` / 每种模式一份材质设置）[10] §4。
4. 配方按材质角色写：pbr / skin / hair / eye / stroke（眉睫）/ glass。XPS 贴图角色的默认接法：diffuse → Base Color；lightmap → AO 相乘；bump → Normal Map（绿通道按清单里的标志）；specular → Specular / Roughness；emission → Emission；mask + microbump → 细节法线（平铺次数取网格名参数）。
5. ROE、剑星、Vindictus 的游戏材质插件作为可选的“配方提供者”继续调用。
6. 报告匹配率，并列出未匹配的材质。

## 10. 表情

- **引擎**：移植 Convert_to_MMD5 的 `expression/` 与 `convert/face.py`（源自你的 expression_kit）。它已经支持每个表情做骨骼 morph 或顶点 morph；AUTO 按“只留 4 个权重时的最大误差 ≤0.3 mm”逐个选择 [10] §5。
- **模式**：面板上三选一：骨骼 / 顶点 / AUTO。XPS 模型通常每顶点不超过 4 个权重，AUTO 几乎会全选骨骼 morph，界面上会说明。
- **名单**：默认 19 个，顺序同 18 系列，也正是你 2024 年清单里的 19 个 [11] §7.1：口 あ、あ２、い、う、え、お、にやり、激怒；目 まばたき、笑い、ウィンク、ウィンク右、びっくり、じと目；眉 困る、怒り、真面目、上、下。可选追加 ん、ω、ウィンク２、ｳｨﾝｸ２右、はぅ、なごみ 等。
- **要新做的部分**：XPS 脸骨角色表（`head jaw`、`head eyelid …`、`head lip …`、`head eyebrow …`、`head tongue …`）；单眼睑骨的配方（闭眼时眼球按侧后退约 6 mm）；`激怒` 的配方，现有工具都没有 [10] §5。
- **顶点 morph**：由骨骼 morph 的姿态烘焙；丢弃 |d| < 1e-4·H 的偏移。18 系列 Bunny 的每个顶点 morph 带约 2 万个噪声顶点 [11] §7.3。
- **可选件开关**：XPS `+`/`-` 可选网格转为材質モーフ（显示/隐藏）[06]。照れ、涙 等材质 morph 列为后续项。

## 11. 物理

四个子面板分别检测、预览、生成、删除；参数来自 `physics_presets.csv`，可以整套切换“硬 / 软”。

| 类别 | 默认 | 依据 |
|---|---|---|
| 身体碰撞体 | 静态胶囊：頭、首、上半身…上半身3、下半身（横放）、肩、腕、ひじ、足、ひざ；四肢 r = 0.2·骨长；躯干半径按网格截面实测（Convert_to_MMD5 `_measured_radius`）；mass 1；阻尼 0.5/0.5；摩擦 0.5 | [11] §13.7、[10] §6 |
| 胸 | 每侧一球，r = 0.029·H，球心在骨头前方 0.020–0.024·H；动态；不与任何组碰撞；Joint 挂 上半身2，平移锁死。“硬”= 三轴 ±10°、无弹簧（18 系列与你的乳奶模板，本机 89% 的胸物理用这套）；“软”= ±30° + 旋转弹簧 30 | [11] §13.7、[10] §6 |
| 臀 | 同胸；球心在骨头后方；Joint 挂 下半身 | [11] §13.7 |
| 头发 | 每段一个胶囊，h = 骨长，r = 0.2·骨长（夹在 0.07–0.35）；mass 1；阻尼 0.9/0.99；摩擦 0；根段静态，或设为不碰身体的动态段；“硬”= ±10° 无弹簧，“软”= ±30° + 弹簧 30 | [11] §13.7；Convert_to_MMD5 hair |
| 衣物 | 调用 `mmd_cloth_physics.api.setup()`（skirt / coat / ribbon / sleeve / tassel / ornament 预设）；18 系列里没有裙子样本 | [10] §6、[11] §8.6 |

- **碰撞组**：界面和 CSV 统一用 PMXE 的 1–16 编号，内部换算成 0–15。换成同一套编号后，18 系列与你的 Convert_to_MMD5 / ROE 约定基本一致：身体 1、头发 10、胸/臀 16（不与任何组碰撞）；只有衣物不同（18 系列用 11，Convert_to_MMD5 用 12）。
- **链的识别**：头发、衣物、胸链按“名称正则 + 几何”给出候选（Convert_to_MMD5 的 `HAIR_RE` / `CLOTH_RE` / `BREAST_RE` 加悬挂链形状），在“其余骨骼”列表里可以改。
- **必须遵守的 MMD 物理规则** [10] §6：欧拉角用 `YXZ`；刚体轴系为右手系；小角度扭转轴落在 PMX 的 Y 轴；弹簧按段长平方缩放；建完关闭 rigidbody world；禁止初始重叠、零尺寸刚体和未绑骨刚体。
