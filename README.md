# XPS → PMX

Blender 3.6 插件：把 XPS / XNALara 模型（`.xps`、`.mesh`、`.mesh.ascii`）转换成 MMD 用的 PMX 模型。

插件的工作：

- 自动识别骨骼，映射到 MMD 标准骨；
- 补全准标准骨；
- 把 T 姿势转成 A 姿势；
- 生成 IK、付与和表示枠；
- 导出后把 PMX 读回来逐项检查，再给整个模型做一次「体检」：把模型摆成常用的几个姿势，用大白话列出哪里有问题、给出修正，还能在视口里定位到出问题的顶点、渲染小图对比修正前后。

平时只用三个按钮：**一键转换** → 看**体检报告** → 需要时勾上修正、点**按修正从头重做**。每根源骨去了哪里、为什么，都能在面板里看到，也能手改；所有改动记在「修正单」里，下次转换同一个 XPS 会自动套用。

> **当前状态（2026-10-31）**：M1–M4 和 M4.5 已完成：导入、骨骼识别与映射、预处理、MMD 骨架与 PMX 导出，以及一键转换、体检（含姿势测试、定位和看图）和修正单。**表情、物理、高清材质回挂还没有做**：现在导出的模型头发和裙子是硬的，也没有表情。

## 能做什么

| 阶段 | 做什么 |
|---|---|
| ① 导入 | 用自写的读取器读 `.xps`（2.x / 3.x）、`.mesh`、`.mesh.ascii`，不依赖 XNALaraMesh。建立骨架、网格、UV、自定义法线、权重和预览材质；权重归一化，每个顶点最多保留 4 根骨。导入后核对顶点、面、骨的数量是否与文件一致 |
| ② 识别 | 判断骨架约定（XNALara 通用名、DAZ G8、Unreal、Bip001 等），按名称表、拓扑和位置把源骨填进 MMD 骨的槽位。其余每根骨给出处置（并入 / 保留 / 删除）和理由。然后做映射检查和下半身诊断 |
| ③ 预处理 | 按处置表合并扭转骨、辅助骨的权重，删除无权重骨；修正朝向；缩放并贴地；手臂转到 A 姿势，烘焙为静止姿态（网格和形态键一起转） |
| ④ 生成 MMD 骨架 | 改成日文骨名；补全标准骨、准标准骨和足D 系；处理下半身和扭转权重；生成 足ＩＫ / つま先ＩＫ、付与、骨序、表示枠；设置材质的 MMD 参数；收编为 mmd_tools 模型 |
| ⑧ 导出 | 以 ×12.5 导出 PMX 并复制贴图，再读回文件逐项检查（骨序、父子、付与、IK、权重、表示枠、贴图），报告写成 JSON；同时保存修正单 |
| ⑨ 体检 | 把前面各步的警告和检查汇成一张报告，再检查最终权重：膝、肘有没有被上一节/下一节扯着走（关节漏权重），偏在一侧的骨有没有带着另一侧的顶点（左右串权重）。然后把模型摆成 15 个测试姿势（弯膝、弯肘、抬臂、转手腕、转上臂、耸肩，左右各一；扭胯、弯腰、转头），按 MMD 的方式算变形，找出跟不上或被带着动的部位、扭转塌陷和接缝裂开。每条写明部位、原因和证据，能修的给出修正；能在视口里定位，也能渲染小图 |

阶段编号按完整设计排列。⑤ 表情、⑥ 物理还没做；原来的 ⑦ 汇总检查并进了 ⑨。

## 还不能做什么

- ⑤ 表情、⑥ 物理、高清材质回挂。
- 体检查不出穿模、物理效果和 MMD 特有的 IK 行为。
- 没有骨骼、或只有一两根骨的道具文件（比如单独的武器 xps）：② 会报错，不能转换。
- Blender 4.x / 5.x 和 mmd_tools 2.x 以上版本。只支持 Blender 3.6 + mmd_tools 1.0.2。
- 只在 Windows 11 上测试过。

## 环境要求

- [Blender 3.6](https://download.blender.org/release/Blender3.6/)（测试用 3.6.15）。
- [mmd_tools 1.0.2](https://github.com/MMD-Blender/blender_mmd_tools/releases/tag/v1.0.2)：④ 和 ⑧ 要用。装上即可；没有勾选时，④ 会临时启用它。

## 安装

**方法一：复制文件夹（普通使用）**

1. 下载本仓库（GitHub 页面上的 Code → Download ZIP）并解压。
2. 把里面的 `xps_to_pmx` 文件夹（直接装着 `__init__.py` 的那一层）整个复制到：

   ```
   %APPDATA%\Blender Foundation\Blender\3.6\scripts\addons\
   ```

   - 不要在 Blender 里用「安装…」直接装下载的 zip：它最外层多了一层 `xps_to_pmx-main` 目录，Blender 找不到插件。
   - 插件目录里如果已经有旧的 `xps_to_pmx` 文件夹，先改名或删除。
3. 打开 Blender 3.6，进入 编辑 → 偏好设置 → 插件：
   - 搜索「XPS」，勾选 **Import-Export: XPS → PMX**；
   - 再搜索「mmd」，勾选 mmd_tools。
4. 展开 XPS → PMX 的插件设置：
   - **PMX 输出根目录**默认是 `D:\xps_exports`，按需修改；
   - **用户数据目录**留空即可（用途见下文「自定义骨骼名表」）。

**方法二：目录联接（开发用，改了代码不用重新复制）**

在 cmd 里运行：

```bat
mklink /J "%APPDATA%\Blender Foundation\Blender\3.6\scripts\addons\xps_to_pmx" "<仓库路径>\xps_to_pmx"
```

改了代码以后，在 Blender 里按 F3 搜索「Reload Scripts」运行，或者重启 Blender。

## 快速上手

1. 在 3D 视图里按 **N** 打开侧栏，切到 **XPS→PMX** 页签。
2. 在顶部路径框里选好 XPS 文件，点 **一键转换**。插件会依次做完 ① 导入、② 识别、③ 预处理、④ 生成骨架、⑧ 导出、⑨ 体检。5 万顶点的模型十几秒，25 万顶点的要一两分钟。
3. 看主面板的**体检报告**（见下一节）：
   - 没有 ✗ 和 ⚠：可以直接去 MMD 里测试；
   - 有问题：勾上那一行右边的修正框，点 **按修正从头重做**。
4. 点「分步模式」→「⑧ 导出 PMX」里的文件夹图标打开导出目录，在 MMD 里打开 PMX 测试。

主面板最后一行总会提示下一步做什么。下次再转换同一个 XPS，上次的修正会自动套用。

**每一步都带截图的完整说明见 [docs/使用说明.md](docs/使用说明.md)。**

## 主面板

### 体检报告

一键转换或重做跑完后，报告列在主面板中间。每一行：

- 行首图标：✗ 错误、⚠ 警告、ℹ 提示；已修复的显示 ✓，已自动修正的显示 AUTO 图标；
- 部位：头部、头发、躯干、左臂、右臂、左腿、右腿、衣物与其他、整体；
- 大白话说明，比如「源文件里有两根骨都叫 “shawl back right 1” …… 动一侧时另一侧也会跟着动」；
- 右边的按钮：**修正勾选框**（这条有修正时才有）、**放大镜**（定位，见下一节）、**眼睛**（忽略：以后不再报）。

选中一行，下面会显示证据数字和修正的具体内容；带姿势的结果还有「定位」「看图」两个按钮。

和上一次体检比，每条会标出：新出现、仍存在、已修复、已自动修正。报告也写进 PMX 旁边的 `<模型名>.report.json`。

现在会报的问题：

| 问题 | 怎么查出来的 | 修正 |
|---|---|---|
| 辅助骨并错了段 | ② 里看每根并入四肢的辅助骨，权重主要落在哪一段 | 改并入权重所在的那一段；明确时**自动修正** |
| 重名骨 | 两根源骨同名，权重全挂在一根上，另一侧那根没有权重 | 按左右拆分权重（会改源权重，要你勾选） |
| 关节漏权重 | ④ 之后看膝、肘两侧中段的顶点，是否带着另一段 ≥10% 的权重 | 能追到是哪根并入骨造成的，就给「改并入」；追不到就写「需要你看」 |
| 左右串权重 | 偏在一侧的骨，在另一侧还带着超过 5% 的权重 | 追到重名骨就给拆分修正；否则写「需要你看」 |
| 姿势测试：跟不上、被带着动 | 把模型摆成测试姿势，按 MMD 的方式算变形，看身体各段该动的有没有跟着动、不该动的有没有被带着动 | 能追到重名骨就给拆分修正；膝、肘的问题并进「关节漏权重」；其余写「需要你看」 |
| 姿势测试：扭转塌陷 | 转手腕、转上臂 90° 时，前臂或上臂的截面缩到原来的 72% 以下（像拧糖纸） | 写「需要你看」：缺少逐段过渡的扭转权重 |
| 姿势测试：接缝裂开 | 静止时重合的两个顶点，在某个姿势里分开到身高的 0.15% 以上 | 写「需要你看」：多半是源模型的接缝权重不一致 |
| 各步的警告 | ① 缺贴图、② 映射检查、③ 拉裂、④ 下半身与材质、⑧ 导出读回 | 按原来的说明处理；「下半身 权重在腰节以上」由扭胯、弯腰两个姿势评判，见「已知问题」 |

姿势测试的姿势、判据和标定见设计文档 §16。它按 MMD 的方式算变形（骨的层级、付与、线性蒙皮），不用 Blender 的约束，所以和你在 MMD 里看到的一致。

### 定位与看图

- **定位**：点结果行的放大镜，或详情里的「定位」。
  - 插件把模型藏起来，换上一份摆好测试姿势的副本，选中出问题的顶点（编辑模式），视口对准那里；
  - 面板顶部会显示「正在预览：……」，点「复位」删掉副本、模型重新显示；
  - 模型本身没有被摆动，导出和从头重做前也会自动复位；
  - 没有姿势的结果，放大镜仍然是选中相关的骨。
- **看图**：点详情里的「看图」，渲染一张测试姿势的小图，出问题的顶点画成红点。
  - 勾了修正再点「按修正从头重做」时，插件会先给这些结果各渲染一张；
  - 重做以后，在同一条结果上点「看图」（已修复的也行），会在同一位置渲染新模型，「上次」「这次」两张并排；
  - 「打开大图」用系统的看图程序打开 PNG。

### 修正单

修正单记着所有和自动结果不一样的决定：

- 你在「分步模式」② 里手改的槽位和处置；
- 导入映射 CSV 时，和当时结果不同的行；
- 体检给出、你勾上的修正，以及自动修正；
- 你忽略的体检结果。

展开主面板下面的「修正单」可以看到每一条：

- 勾选框：取消勾选就是撤销，下次重做时生效；
- 来源：手改、映射CSV、体检、文件；自动加入的标「自动」；
- X：删除这一条。自动修正只会撤销、保留记录，这样以后不会再被自动加回来。

**记住修正**：每次导出时，修正单连同这个模型的选项（缩放、A 姿势、④ 的选项）存两份，同一个 XPS 下次导入（一键或只导入）时自动套用，报告里会写「套用了上次的修正单（n 条）」：

- PMX 旁边的 `<模型名>.fixes.json`；
- 用户数据目录里的 `fixes\<XPS 文件的 SHA-1>.fixes.json`：按文件内容找，换了导出位置也能找到。

XPS 文件内容变了（SHA-1 不同）就不套用，只提示。「修正单」面板里也能手动导入、导出。

### 重做按钮

| 按钮 | 做什么 |
|---|---|
| 按修正从头重做 | 删掉这个模型生成的所有对象，重新导入同一个 XPS，按当前修正单和选项一直做到 ⑨ 体检，并和上一次体检对比 |
| 分步重做 | 同上，但停在 ②，让你在「分步模式」里改映射或选项；改完点「继续」 |
| 继续 | 从当前阶段一直做到 ⑨（还没生成骨架时才能点，比如分步重做之后） |

修正单在生成骨架之后又改过时，主面板会提示「修正单改过，点「按修正从头重做」才生效」。

## 分步模式（高级）

主面板下面的「分步模式（高级）」默认折叠，里面是逐步操作用的 ① ② ③ ④ ⑧。一般只在两种时候用：分步重做后要改映射，或者想一步一步看每个阶段的结果。

### ① 导入

- 路径框填好后点「① 只导入」。路径框是空的时候点这个按钮，会弹出文件选择框。只导入也会套用记住的修正单。
- 也可以用 文件 → 导入 →「XPS → PMX：XPS 模型」。
- 导入完成后，报告框会显示骨数、网格数和顶点数。下面几种警告要留意：
  - 「骨名…过长或重复，Blender 改为…」：名字超长被截断；重名骨会在体检里单独报告。
  - 「找不到贴图…」：导出后这些材质会缺贴图。
  - 「…个顶点受超过 4 根骨影响，已保留最大的 4 个」「…个顶点的权重和不为 1，已归一化」：一般不用管。
- 同一个场景里可以导入多个模型。选中哪个模型的骨架或网格，面板就切换到哪个模型。

### ② 骨骼映射

点「② 自动识别」后，面板分成下面几块。

**槽位**：分为躯干与控制骨、左右对称骨、手指三块。每一行是一根 MMD 骨，右边是填进去的源骨；名字后面带 `*` 的是必需骨。行首的图标表示状态：

| 图标 | 意思 |
|---|---|
| ✓ | 已映射，检查通过 |
| ✎ | 你手改过（记在修正单里）；再次自动识别时不会被覆盖 |
| ＋ | 留空，④ 会按规则生成 |
| · | 留空，也不会生成（源模型本来就没有，比如缺的手指节） |
| ⚠ | 有警告 |
| ✗ | 有错误，比如必需骨缺失、左右放反、层级不对 |

改一个槽位有三种方法：

- 在视口的姿态模式里选中正确的骨，再点那一行的**吸管**按钮；
- 点下拉框，直接搜索骨名；
- 鼠标停在下拉框上按 **Backspace** 清空，表示这根骨交给 ④ 生成（如果它是会生成的骨）。

改完以后点「**检查映射**」重新检查。检查结果里每条后面的放大镜按钮，可以在视口里选中相关的骨。

**下半身诊断**：游戏骨架经常没有标准的 下半身。这一栏说明源骨架属于哪种情形，以及 ④ 会怎样构造 下半身：

| 情形 | 源骨架 | ④ 的处理 |
|---|---|---|
| A | 有干净的髋骨 | 直接用它 |
| B | 髋部权重在 `unused bip001 pelvis` 之类的辅助骨上 | 并入 下半身 |
| C | 髋骨同时管着下腹 | 按高度把权重切分给 下半身 和 上半身 |
| D | 完全没有髋骨 | 从最低的脊柱节按高度切分出 下半身 |

**其余骨骼**：除槽位主骨以外，每根骨的处置有三种：

- 并入：权重并到某个槽位的骨上，然后删除这根骨；
- 保留：作为非标准骨留下，比如脸、头发、衣物上的骨；
- 删除：这根骨没有权重。

右上角的下拉框可以筛选。选中一行，下面会显示理由，比如「肢体辅助骨：头在 left_thigh_bone 段，但 100% 的明确权重在 left_knee_bone 段，按权重所在段并入」。处置和并入目标都可以在行内修改；目标显示的是槽位 id，比如 `left_knee_bone` 就是 左ひざ。

**映射 CSV**：「约定：…」那一行右边有三个图标，依次是：

1. 导入映射 CSV：和当前结果不同的行记进修正单，标成手动。要先点「② 自动识别」，这个按钮才能用；
2. 导出映射 CSV；
3. 清除所有手动修改（包括修正单里的手改和 CSV 条目），回到全自动识别。

还有 ✗ 错误时，③ 不让执行。

③ 会真正合并、删除骨骼，④ 之后整个映射锁定。之后再要改映射，点主面板的「分步重做」：它从头导入、带上修正单、停在 ②。

### ③ 预处理

选项：

- **缩放**，三选一：
  - 肩高归一（默认）：导出后 腕 的高度等于「肩高目标」17.0，与 18 系列成品一致；
  - ×12.5 原尺寸；
  - ×10。
- **A 姿势**，四选一：
  - 37.5° 直臂（默认，18 系列的做法）；
  - あにまさ 29.72°+40.28°；
  - 45° 直臂；
  - 自定义：自己填上臂角和前臂附加角。
- **摆平肩骨**：把 肩 的头移到与 腕 同高、同深的位置。只改骨，不改网格。

> 「18 系列」是一组手工精修过的参考 PMX 成品。插件的不少默认值，比如肩高 17.0、A 姿势 37.5°、扭转权重的分布，都是从它们实测得来的。

点「③ 预处理」后，面板会显示这些结果：

- 缩放倍数、肩高、身高；
- 左右上臂和前臂的角度；
- 拉裂边的数量：A 姿势转换后被拉长 3 倍以上的边。正常是 0；不是 0 时，报告会提示检查腋下和手腕的权重。

如果模型背朝前方，③ 会先把它转 180°。

### ④ 生成 MMD 骨架

选项（默认值就是测试时用的设置）：

- **准标准骨**：生成 上半身2（源模型没有时）、肩P/肩C、腕捩/手捩、腰キャンセル、ダミー、親指０、操作中心；
- **足D 系**：生成 足D/ひざD/足首D/足先EX，腿部权重全部移到 D 骨上；
- **扭转权重**：18 系列阶梯带（默认），或平滑；
- **IK 参数**：あにまさ标准（默认），或 18 系列。

点「④ 生成 MMD 骨架」。完成后模型变成 mmd_tools 模型，② 的映射和 ④ 的选项都变成只读；要换，点主面板的「分步重做」，改完点「继续」。

如果报告里有「下半身 有 x% 的权重在腰节以上」这类警告，请对照 `docs/test/M4_MMD测试清单.md` 第 4 节判断要不要处理。

### ⑧ 导出 PMX

- 路径框留空时，导出到 `<PMX 输出根目录>\<模型名>\<模型名>.pmx`。也可以填一个完整的 `.pmx` 路径。
- 导出时做这几件事：
  - 把贴图复制到 PMX 旁边的 `textures\`；
  - 写出 `<模型名>.report.json`；
  - 把 PMX 读回来逐项检查，结果显示在报告框里；
  - 一键转换和重做时还会保存修正单（见上文「记住修正」）。
- 文件夹图标用来打开导出目录。
- 可以重复导出；同名文件会被覆盖。

## 做错了怎么办

| 想做什么 | 怎么做 |
|---|---|
| 修体检报的问题 | 勾上那一行的修正 → 点「按修正从头重做」 |
| 撤销一条修正 | 在「修正单」里取消勾选 → 点「按修正从头重做」 |
| 自己改映射 | 「分步重做」→ 在「分步模式」② 里改 → 点「继续」 |
| 换 ③ 或 ④ 的选项（缩放、A 姿势、IK…） | 「分步重做」→ 在 ③ / ④ 面板里改 → 点「继续」 |
| 某条结果确认没问题 | 点那一行的眼睛（忽略），以后不再报 |

从头重做时，选项和修正单都会带过去；旧的模型对象会被删掉，导出到同一个位置的 PMX 会被覆盖。

## 批量转换（命令行，不开界面）

```bat
"D:\Program Files\blender-3.6.15-windows-x64\blender.exe" -b --factory-startup ^
  --python "<仓库路径>\scripts\convert_xps.py" -- ^
  "E:\models\a\xps.xps" "E:\models\b\xps.xps" --out D:\xps_exports --blend
```

- 和面板的「一键转换」是同一套流程：对每个文件做 ① ② ③ ④ ⑧ ⑨，打印每一步的结果和体检报告。
- 每个文件记住的修正单会自动套用，所以在界面里修过一次的模型，批量转换时也是修好的。
- 某个模型在哪一步出错，就停在那一步，然后接着处理下一个模型。映射检查有错误的模型会停在 ②，要回到界面里处理。
- 参数：
  - `--out`：输出根目录，默认 `D:\xps_exports`；
  - `--blend`：把转换后的场景另存为 `.blend`，方便回头在 Blender 里检查；
  - `--fixes <文件>`：所有模型都用这个修正单文件；
  - `--no-fixes`：不套用记住的修正单。
- 脚本直接从仓库加载插件，不需要先在 Blender 里安装它；mmd_tools 仍然要装在 Blender 3.6 里。
- 上面是 cmd 的写法。在 PowerShell 里，命令开头要加 `&`，续行符换成反引号。

## 已知问题

1. **重名骨要手动确认拆分**：体检能找出来并给出拆分修正，但拆分会改源权重，所以要你勾选后重做。这类源文件往往连父骨也挂错了（rouffe 右边的披肩挂在左边的骨下面），拆分时会一并改挂到同侧。
2. **下半身权重提示**：有的源模型的髋骨一直覆盖到肚子，④ 会报「下半身 有 x% 的权重在腰节以上」。体检用扭胯、弯腰两个姿势评判：18 系列成品的肚子也会被胯带动，最多约身高的 3.5%。不超过这个程度就降为提示，并写明「18 系列成品也是这样」；超过才保留警告，可以定位、看图。
3. **体检查不到的**：穿模、物理效果、MMD 特有的 IK 行为。你在 MMD 里发现的问题告诉我，我会把它变成新的检查项。
4. **用 mmd_tools 把 PMX 导入 Blender 预览时**，部分付与会受骨的 roll 影响：我们导出的模型转 左手捩 时，左手捩2/3 在 Blender 里会多转（63°/83°，应为 45°/67.5°）。MMD 里没有这个问题，姿势测试也不受影响。

## 验证情况

- **自动测试**（2026-10-31）：离线测试 178 项；Blender 无头端到端测试 M1 导入 68 项、M2 识别 66 项、M3 预处理 65 项、M4 骨架 + 导出 + 从头重做 96 项、M4.5 一键与体检 86 项、界面绘制 13 项。全部通过。运行方法见下文「测试」。
- **识别**：在本机 165 个 XPS 角色模型上做过统计。
  - 骨架约定：XNALara 通用名 122 个、DAZ G8 33 个、Auto-Rig Pro 4 个、Bip001 4 个、Unreal 1 个、ValveBiped 1 个。
  - 必需槽位全部自动填上：165/165。
  - 没有错误级检查：164/165。
- **分类器改动的影响**（M4.5，本机 163 个去重后的角色文件逐根对比）：76 个模型、559 根骨的处置或类别有变化，逐类核对都是有意的修正。主要是：蝴蝶结从「道具」改为衣物（210 根）；肘部、肩胛的校正骨不再被当成道具，改为并入手臂（约 170 根）；按权重换了并入段的辅助骨（66 根）。明细见设计文档 §15.7。
- **体检**：
  - 18 系列 10 个成品读入后跑症状检查：关节漏权重、左右串权重都是 0 条。
  - 姿势测试（最终代码，严格阈值）：18 系列 10 个成品里只有 Emilie de Rochefort 的前臂扭转塌陷（成品里真实存在）；4 个回归模型 0 条；rouffe 新导出只剩重名披肩，旧分类器的导出能抓到膝、肘并错段。数字见设计文档 §16.7。
  - rouffe 用旧分类器导出的模型：膝、肘的漏权重和披肩的左右串权重都被报出；新流程导出的模型膝、肘干净，披肩的两组重名骨被报出，勾选拆分后重做即消失。
  - 本机全部 165 个样本跑原因检查：重名骨 3 条（2 个模型，都是 rouffe 系列）；并入段不对 4 条（Wonder Woman 两个版本的前臂校正骨 `c_forearm_bend`，名称表把它并进了上臂，会被自动改并到前臂）。
- **完整转换**：在 4 个回归模型和 rouffe 上验证过，回归模型分别是 XNALara 通用名、DAZ G8、Stellar Blade Eve（主骨无权重）和 Unreal 命名。
  - 导出读回检查零警告；一键转换后体检没有错误，警告只有已知的下半身提示和 rouffe 的重名骨。
  - 用 mmd_tools 在 Blender 里回放舞蹈 VMD 抽查（M4 时）：脚的最低点在 −4 mm～0 之间，与 18 系列成品相同，没有网格爆炸。
  - 在 MMD 里的实测清单见 `docs/test/M4_MMD测试清单.md`。
