# XPS → PMX

Blender 3.6 插件：把 XPS / XNALara 模型（`.xps`、`.mesh`、`.mesh.ascii`）转换成 MMD 用的 PMX 模型。

插件的工作：

- 自动识别骨骼，映射到 MMD 标准骨；
- 补全准标准骨；
- 把 T 姿势转成 A 姿势；
- 生成 IK、付与和表示枠；
- 导出后把 PMX 读回来逐项检查。

每根源骨去了哪里、为什么，都能在面板里看到，也能手改。映射可以存成 CSV 复用。

> **当前状态（2026-10-25）**：M1–M4 已完成，包括导入、骨骼识别与映射、预处理、MMD 骨架与 PMX 导出。**表情、物理、高清材质回挂还没有做**：现在导出的模型头发和裙子是硬的，也没有表情。

## 能做什么

| 阶段 | 做什么 |
|---|---|
| ① 导入 | 用自写的读取器读 `.xps`（2.x / 3.x）、`.mesh`、`.mesh.ascii`，不依赖 XNALaraMesh。建立骨架、网格、UV、自定义法线、权重和预览材质；权重归一化，每个顶点最多保留 4 根骨。导入后核对顶点、面、骨的数量是否与文件一致 |
| ② 识别 | 判断骨架约定（XNALara 通用名、DAZ G8、Unreal、Bip001 等），按名称表、拓扑和位置把源骨填进 MMD 骨的槽位。其余每根骨给出处置（并入 / 保留 / 删除）和理由。然后做映射检查和下半身诊断 |
| ③ 预处理 | 按处置表合并扭转骨、辅助骨的权重，删除无权重骨；修正朝向；缩放并贴地；手臂转到 A 姿势，烘焙为静止姿态（网格和形态键一起转） |
| ④ 生成 MMD 骨架 | 改成日文骨名；补全标准骨、准标准骨和足D 系；处理下半身和扭转权重；生成 足ＩＫ / つま先ＩＫ、付与、骨序、表示枠；设置材质的 MMD 参数；收编为 mmd_tools 模型 |
| ⑧ 导出 | 以 ×12.5 导出 PMX 并复制贴图，再读回文件逐项检查（骨序、父子、付与、IK、权重、表示枠、贴图），报告写成 JSON |

阶段编号按完整设计排列。⑤ 表情、⑥ 物理、⑦ 汇总检查还没做，所以面板上 ④ 之后直接是 ⑧。

## 还不能做什么

- ⑤ 表情、⑥ 物理、⑦ 汇总检查、高清材质回挂。
- 没有骨骼、或只有一两根骨的道具文件（比如单独的武器 xps）：② 会报错，不能转换。
- Blender 4.x / 5.x 和 mmd_tools 2.x 以上版本。只支持 Blender 3.6 + mmd_tools 1.0.2。
- 只在 Windows 11 上测试过。

## 环境要求

- [Blender 3.6](https://download.blender.org/release/Blender3.6/)（测试用 3.6.15）。
- [mmd_tools 1.0.2](https://github.com/MMD-Blender/blender_mmd_tools/releases/tag/v1.0.2)：④ 和 ⑧ 要用。装上即可；没有勾选时，④ 会临时启用它。

## 安装

**方法一：复制文件夹（普通使用）**

1. 下载本仓库（GitHub 页面上的 Code → Download ZIP）并解压。
2. 把里面的 `xps_to_pmx` 文件夹（直接装着 `__init__.py` 的那一层）整个复制到：

   ```
   %APPDATA%\Blender Foundation\Blender\3.6\scripts\addons\
   ```

   - 不要在 Blender 里用「安装…」直接装下载的 zip：它最外层多了一层 `xps_to_pmx-main` 目录，Blender 找不到插件。
   - 插件目录里如果已经有旧的 `xps_to_pmx` 文件夹，先改名或删除。
3. 打开 Blender 3.6，进入 编辑 → 偏好设置 → 插件：
   - 搜索「XPS」，勾选 **Import-Export: XPS → PMX**；
   - 再搜索「mmd」，勾选 mmd_tools。
4. 展开 XPS → PMX 的插件设置：
   - **PMX 输出根目录**默认是 `D:\xps_exports`，按需修改；
   - **用户数据目录**留空即可（用途见下文「自定义骨骼名表」）。

**方法二：目录联接（开发用，改了代码不用重新复制）**

在 cmd 里运行：

```bat
mklink /J "%APPDATA%\Blender Foundation\Blender\3.6\scripts\addons\xps_to_pmx" "<仓库路径>\xps_to_pmx"
```

改了代码以后，在 Blender 里按 F3 搜索「Reload Scripts」运行，或者重启 Blender。

## 快速上手：用默认设置转换一个模型

1. 在 3D 视图里按 **N** 打开侧栏，切到 **XPS→PMX** 页签。
2. 在顶部路径框里选好 XPS 文件，点 **① 导入**。
3. 在「② 骨骼映射」里点 **② 自动识别**，然后看下面的「检查结果」：
   - 有 ✗ 错误时，按下文「② 骨骼映射」一节修改，直到没有错误为止。
4. 点「约定：…」那一行的**导出**图标，存一份映射 CSV。以后要重做时会用到。
5. 依次点 **③ 预处理**、**④ 生成 MMD 骨架**、**⑧ 导出 PMX**。这三个面板默认是折叠的，点标题展开。
6. 点 ⑧ 旁边的文件夹图标打开导出目录，在 MMD 里打开 PMX 测试。

主面板报告框的最后一行总会提示下一步做什么。

## 分步说明

### ① 导入

- 路径框填好后点「① 导入」。路径框是空的时候点这个按钮，会弹出文件选择框。
- 也可以用 文件 → 导入 →「XPS → PMX：XPS 模型」。
- 导入完成后，报告框会显示骨数、网格数和顶点数。下面几种警告要留意：
  - 「骨名…过长或重复，Blender 改为…」：源文件里可能有重名骨，见「已知问题」第 3 条。
  - 「找不到贴图…」：导出后这些材质会缺贴图。
  - 「…个顶点受超过 4 根骨影响，已保留最大的 4 个」「…个顶点的权重和不为 1，已归一化」：一般不用管。
- 同一个场景里可以导入多个模型。选中哪个模型的骨架或网格，面板就切换到哪个模型。

### ② 骨骼映射

点「② 自动识别」后，面板分成下面几块。

**槽位**：分为躯干与控制骨、左右对称骨、手指三块。每一行是一根 MMD 骨，右边是填进去的源骨；名字后面带 `*` 的是必需骨。行首的图标表示状态：

| 图标 | 意思 |
|---|---|
| ✓ | 已映射，检查通过 |
| ✎ | 你手改过；再次自动识别时不会被覆盖 |
| ＋ | 留空，④ 会按规则生成 |
| · | 留空，也不会生成（源模型本来就没有，比如缺的手指节） |
| ⚠ | 有警告 |
| ✗ | 有错误，比如必需骨缺失、左右放反、层级不对 |

改一个槽位有三种方法：

- 在视口的姿态模式里选中正确的骨，再点那一行的**吸管**按钮；
- 点下拉框，直接搜索骨名；
- 鼠标停在下拉框上按 **Backspace** 清空，表示这根骨交给 ④ 生成（如果它是会生成的骨）。

改完以后点「**检查映射**」重新检查。检查结果里每条后面的放大镜按钮，可以在视口里选中相关的骨。

**下半身诊断**：游戏骨架经常没有标准的 下半身。这一栏说明源骨架属于哪种情形，以及 ④ 会怎样构造 下半身：

| 情形 | 源骨架 | ④ 的处理 |
|---|---|---|
| A | 有干净的髋骨 | 直接用它 |
| B | 髋部权重在 `unused bip001 pelvis` 之类的辅助骨上 | 并入 下半身 |
| C | 髋骨同时管着下腹 | 按高度把权重切分给 下半身 和 上半身 |
| D | 完全没有髋骨 | 从最低的脊柱节按高度切分出 下半身 |

**其余骨骼**：除槽位主骨以外，每根骨的处置有三种：

- 并入：权重并到某个槽位的骨上，然后删除这根骨；
- 保留：作为非标准骨留下，比如脸、头发、衣物上的骨；
- 删除：这根骨没有权重。

右上角的下拉框可以筛选。选中一行，下面会显示理由。处置和并入目标都可以在行内修改；目标显示的是槽位 id，比如 `left_knee_bone` 就是 左ひざ。

**映射 CSV**：「约定：…」那一行右边有三个图标，依次是：

1. 导入映射 CSV：导入的行都标成手动；
2. 导出映射 CSV；
3. 清除所有手动修改，回到全自动识别。

**导入 CSV 之前要先点「② 自动识别」**，否则所有行都对不上。

还有 ✗ 错误时，③ 不让执行。

> **建议在点 ③ 之前导出一份映射 CSV。**
> - ③ 会真正合并、删除骨骼。做完 ③，「其余骨骼」里就看不到已经并入的骨了。
> - ④ 之后，整个映射都会锁定。
>
> 到那时再要改映射，就得重新导入模型，再载入这份 CSV。具体做法见「做错了怎么办」。

### ③ 预处理

选项：

- **缩放**，三选一：
  - 肩高归一（默认）：导出后 腕 的高度等于「肩高目标」17.0，与 18 系列成品一致；
  - ×12.5 原尺寸；
  - ×10。
- **A 姿势**，四选一：
  - 37.5° 直臂（默认，18 系列的做法）；
  - あにまさ 29.72°+40.28°；
  - 45° 直臂；
  - 自定义：自己填上臂角和前臂附加角。
- **摆平肩骨**：把 肩 的头移到与 腕 同高、同深的位置。只改骨，不改网格。

> 「18 系列」是一组手工精修过的参考 PMX 成品。插件的不少默认值，比如肩高 17.0、A 姿势 37.5°、扭转权重的分布，都是从它们实测得来的。

点「③ 预处理」后，面板会显示这些结果：

- 缩放倍数、肩高、身高；
- 左右上臂和前臂的角度；
- 拉裂边的数量：A 姿势转换后被拉长 3 倍以上的边。正常是 0；不是 0 时，报告会提示检查腋下和手腕的权重。

如果模型背朝前方，③ 会先把它转 180°。

### ④ 生成 MMD 骨架

选项（默认值就是测试时用的设置）：

- **准标准骨**：生成 上半身2（源模型没有时）、肩P/肩C、腕捩/手捩、腰キャンセル、ダミー、親指０、操作中心；
- **足D 系**：生成 足D/ひざD/足首D/足先EX，腿部权重全部移到 D 骨上；
- **扭转权重**：18 系列阶梯带（默认），或平滑；
- **IK 参数**：あにまさ标准（默认），或 18 系列。

点「④ 生成 MMD 骨架」。完成后模型变成 mmd_tools 模型，② 的映射和 ④ 的选项都变成只读。

如果报告里有「下半身 有 x% 的权重在腰节以上」这类警告，请对照 `docs/test/M4_MMD测试清单.md` 第 4 节判断要不要处理。

### ⑧ 导出 PMX

- 路径框留空时，导出到 `<PMX 输出根目录>\<模型名>\<模型名>.pmx`。也可以填一个完整的 `.pmx` 路径。
- 导出时做三件事：
  - 把贴图复制到 PMX 旁边的 `textures\`；
  - 写出 `<模型名>.report.json`；
  - 把 PMX 读回来逐项检查，结果显示在报告框里。
- 文件夹图标用来打开导出目录。
- 可以重复导出；同名文件会被覆盖。

## 做错了怎么办

| 什么时候发现 | 要改什么 | 怎么做 |
|---|---|---|
| ③ 之前 | 映射 | 在 ② 里直接改，然后点「检查映射」 |
| ④ 之前 | ④ 的选项 | 直接改，再点 ④ |
| ③ 之后（包括 ④、⑧ 之后） | ③ 的选项：缩放、A 姿势、摆平肩骨 | 在 ③ 面板改好选项 → 点主面板的**重来** → 需要的话再点 ⑧ |
| ③ 之后（包括 ④、⑧ 之后） | 映射；或者 ④ 已经做完，想换 ④ 的选项 | 重新 **① 导入**同一个 XPS → **② 自动识别** → 导入之前备份的映射 CSV → 修改 → 检查映射 → ③ ④ ⑧ |

**重来**按钮在主面板「已完成」那一行，会做这些事：

1. 删掉这个模型生成的所有对象；
2. 重新导入同一个 XPS；
3. 套用原来的全部选项，以及你手改过的槽位和处置；
4. 自动重跑到原来到达的阶段。最多跑到 ④，不会自动导出。

它不会停在 ②，所以**不能用来改映射**。② 面板上「要改映射：『重来』后重新识别」这句提示目前是错的，见「已知问题」第 1 条。

关于重新导入：

- 重新导入的模型是一个新任务，选项都是默认值。之前改过 ③、④ 的选项，要重新设一遍。
- 没有备份 CSV 的话，就在 ② 里把手改的地方重新改一遍。
- 旧的模型还留在场景里。可以在大纲视图里把它的集合删掉，也可以不管：只要两次都用默认导出路径，新导出的 PMX 会覆盖旧的。

## 批量转换（命令行，不开界面）

```bat
"D:\Program Files\blender-3.6.15-windows-x64\blender.exe" -b --factory-startup ^
  --python "<仓库路径>\scripts\convert_xps.py" -- ^
  "E:\models\a\xps.xps" "E:\models\b\xps.xps" --out D:\xps_exports --blend
```

- 用默认选项对每个文件依次跑 ① ② ③ ④ ⑧，打印每一步的错误和警告。
- 某个模型在哪一步出错，就停在那一步，然后接着处理下一个模型。
- 映射检查有错误的模型会停在 ②，因为批量模式没法手改映射。这类模型要回到界面里处理。
- 参数：
  - `--out`：输出根目录，默认 `D:\xps_exports`；
  - `--blend`：把转换后的场景另存为 `.blend`，方便回头在 Blender 里检查。
- 脚本直接从仓库加载插件，不需要先在 Blender 里安装它；mmd_tools 仍然要装在 Blender 3.6 里。
- 上面是 cmd 的写法。在 PowerShell 里，命令开头要加 `&`，续行符换成反引号。

## 输出文件

```
<输出根目录>\<模型名>\
  <模型名>.pmx           PMX 2.0
  textures\              复制过来的贴图
  <模型名>.report.json   各阶段的报告和导出读回检查
  <模型名>.blend         只有批量脚本加 --blend 时才有
```

## 已知问题

这几条会在下一版修。

1. **『重来』回不到 ②**
   - 『重来』会自动重跑到原来的阶段，所以 ④ 之后映射和 ④ 的选项仍然锁定。
   - ② 面板上「要改映射：『重来』后重新识别」的提示是错的。
   - 现在请按「做错了怎么办」里重新导入的方法处理。
2. **关节处的扭转骨、辅助骨被并到上一节**
   - 哪些骨：在从 3ds Max Biped 转来的 XNALara 骨架里，有些辅助骨的头在关节上，父骨是上一节，权重却在下一节。例如：
     - `unused bip001 lcalftwist`：小腿扭转骨，权重在小腿上段；
     - rouffe 模型的 `unused trash 18/19`：权重在前臂上。
   - 后果：插件现在按父骨把它们并入 足 或 腕。弯膝、弯肘时，小腿上段或袖子会被大腿、上臂扯着走。
   - 临时办法，要在 ③ 之前做：
     1. 在「其余骨骼」里筛选「并入」，找名字带 twist、或者理由写着「位于肢体骨段上的辅助/扭转骨」的骨。
     2. 选中网格，进入权重绘制模式，选这根骨的顶点组，看权重在关节哪一侧。
     3. 如果在下一节，就把这根骨的目标改成下一节的槽位，然后点「检查映射」：
        - 左/右ひざ：`left_knee_bone` / `right_knee_bone`；
        - 左/右ひじ：`left_lower_arm_bone` / `right_lower_arm_bone`。
3. **重名骨**
   - 源文件里两根骨同名时，导入报告会提示「骨名…重复，Blender 改为…」。这时两根骨的权重可能全挂在第一根上。
   - 例如 rouffe 模型的 `shawl back right 1/2`：动 左肩 时，披肩的右半边也跟着动。
   - 插件现在还不会自动拆分。
4. **分类不准**
   - 名字带 fringe（流苏）、lip（嘴唇）的骨可能被归成头发，进了 髪 表示枠，也用了 髪 开头的短名。
   - 不影响动作；做物理（M7）之前会修。
5. **下半身权重提示**
   - 有的源模型的髋骨一直覆盖到肚子，④ 会提示「下半身 有 x% 的权重在腰节以上」。
   - 要不要处理，看 MMD 里扭腰时肚子会不会跟着胯走。详见 `docs/test/M4_MMD测试清单.md` 第 4 节。

## 验证情况

- **自动测试**（2026-10-25）：离线测试 123 项；Blender 无头端到端测试 M1 导入 68 项、M2 识别 66 项、M3 预处理 65 项、M4 骨架 + 导出 + 重来 95 项、界面绘制 7 项。全部通过。运行方法见下文「测试」。
- **识别**：在本机 165 个 XPS 角色模型上做过统计。
  - 骨架约定：XNALara 通用名 122 个、DAZ G8 33 个、Auto-Rig Pro 4 个、Bip001 4 个、Unreal 1 个、ValveBiped 1 个。
  - 必需槽位全部自动填上：165/165。
  - 没有错误级检查：164/165。
- **完整转换**：在 4 个回归模型上验证过，分别是 XNALara 通用名、DAZ G8、Stellar Blade Eve（主骨无权重）和 Unreal 命名。
  - 导出读回检查零警告。
  - 用 mmd_tools 在 Blender 里回放舞蹈 VMD 抽查：脚的最低点在 −4 mm～0 之间，与 18 系列成品相同，没有网格爆炸。
  - 在 MMD 里的实测清单见 `docs/test/M4_MMD测试清单.md`。

## 开发

### 目录

```
xps_to_pmx/            插件包
  core/                纯 Python，不依赖 bpy：XPS 读取、骨骼规格、识别、检查、骨架计划、权重规则
  blender/             bpy 适配层；只有 mmdtools_bridge.py 调用 mmd_tools
  pipeline/            各阶段函数，界面和批量脚本共用同一套
  ops/  ui/            操作符与面板
  data/bone_slots.csv  骨骼规格，加上各骨架约定的别名（插件里唯一的骨名表）
tests/                 离线测试（pytest）
tests_blender/         Blender 无头端到端测试；回归模型的路径在 regression_models.json
scripts/               批量转换、测试运行、样本统计
docs/                  调研笔记、实施设计、测试清单
```

### 测试

```bat
:: 离线测试：需要 Python 3.10+、pytest、numpy
python -m pytest

:: Blender 端到端测试：默认用 D:\Program Files\blender-3.6.15-windows-x64\blender.exe，
:: 可以用环境变量 XPS2PMX_BLENDER 指定别的位置
python scripts\run_blender_tests.py
python scripts\run_blender_tests.py m4_build -- --models daz_purifier_inase
```

回归模型文件不在仓库里，路径写在 `tests_blender/regression_models.json`；找不到的模型会跳过。

### 自定义骨骼名表

在偏好设置的「用户数据目录」里放一个 `bone_slots.csv`，格式与 `xps_to_pmx/data/bone_slots.csv` 相同：

- slot_id 相同的行，整行替换默认表里的那一行；
- 新增的列作为新的骨架约定。

格式说明见设计文档 §5.1。
